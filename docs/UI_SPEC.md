# 화면 기준 — 대시보드

- 작성: 2026-11-16 (세 번째 판). **기준은 대표가 넣은 목업**이다.
  - 목업 원본: [`design/jg_agent_astra_editorial_mockup.html`](design/jg_agent_astra_editorial_mockup.html) (모양과 CSS의 출발점), [`design/jg_agent_astra_editorial_mockup.png`](design/jg_agent_astra_editorial_mockup.png) (렌더링한 모습)
  - 그 전에 대표가 준 레퍼런스 이미지 두 장(어두운 보라, 밝은 베이지)은 **기능 목록의 출처**로만 쓴다. 대표 지시: "레퍼런스 이미지에만 있고 목업에 없는 것은 추가한다(시스템 상태 등)." 그 목록이 3절이다.
- 목업과 이 문서가 다르면 이 문서가 우선이다.
- 구조와 규칙은 [DESIGN.md](DESIGN.md), 단계는 [STAGES.md](STAGES.md)가 기준이다. 이 문서는 화면만 다룬다.

## 1. 대표 지시 (2026-11-16)

- 화면 모양은 목업(검정 바탕, 금색 포인트, 명조 제목의 잡지 같은 구성)을 따른다
- 레퍼런스 이미지에만 있던 기능 요소는 목업 모양에 맞춰 추가한다
- 3열 메인: 영상 탐색 / AI 분석 및 댓글 초안 / 실행 관리
- 탭, 검색, 선택, 상태 표시가 실제로 동작
- 좁은 화면에서는 반응형
- 목업의 수치와 영상은 가상 데이터다. 실제 데이터와 연결한다
- 댓글은 광고 관계를 명확히 표시하고 사용자가 최종 검토한다
- 기존 FastAPI 구조와 백엔드 기능 유지. 기존 API를 지우거나 임의로 바꾸지 않는다

## 2. 화면 구성 (목업 그대로)

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 위 줄: JG 로고 │ 메뉴(DASHBOARD·DISCOVER·ANALYZE·ACTIVITY…) │ 시스템 상태 │
├──────────────────────────────────────────────────────────────────────┤
│ 제목 영역: 작은 금색 표제 + 명조 큰 제목 + 설명        │ 오늘 통계 4개      │
├──────────────────────────────────────────────────────────────────────┤
│ 흐름 띠: [01] DISCOVER 영상 탐색 ─ [02] UNDERSTAND AI 분석·초안 ─ [03] EXECUTE │
├──────────────────────┬──────────────────────┬────────────────────────┤
│ 영상 탐색     01 / 03 │ AI 분석과 댓글 초안 02/03│ 실행 및 관리    03 / 03 │
│ 탭: 키워드 / URL      │ 선택한 영상 카드        │ 브라우저 환경(설정 4줄)  │
│ 검색창 + [영상 찾기]   │ 영상 맥락 분석          │ 작업 상자: 안내 + 큰 버튼 │
│ 거르기 3개            │ 댓글 초안 + 글자 수      │   + 진행 단계 표시       │
│ 영상 목록(하나 선택)   │ 규칙 검사 · 다른 초안    │ OPERATION NOTE         │
├──────────────────────┴──────────────────────┴────────────────────────┤
│ 작업 기록 (전체 너비 표)                                                │
└──────────────────────────────────────────────────────────────────────┘
```

사이드바는 없다. 레퍼런스 이미지의 사이드바에 있던 것(메뉴, 시스템 상태, 버전)은 위 줄과 제목 영역에 넣는다.

### 2.1 위 줄

- 왼쪽: `JG` 로고 + `MARKETING / AI AGENT`.
- 가운데: 메뉴. 목업의 네 개(DASHBOARD · DISCOVER · ANALYZE · ACTIVITY)에 `EXECUTE`와 `SETTINGS`를 더한다. 한 화면짜리 앱이라 누르면 해당 칸으로 이동(잠깐 강조)하고, SETTINGS는 같은 화면의 패널로 연다.
  - 9단계: 한국어 이름을 위에, 영어는 작게 아래에 둔다(대시보드 · 영상 탐색 · 분석 · 실행 · 기록 · 설정). 지금 있는 칸을 메뉴에 금색 밑줄로 표시한다(9절).
- 오른쪽: **시스템 상태**(3절 A1). 목업의 `LOCAL SYSTEM` 점 하나 자리에 세 개를 둔다.
- 목업의 `DESIGN PREVIEW · 01`은 넣지 않는다.

### 2.2 제목 영역

- 금색 작은 표제 `INTELLIGENT CONTENT WORKFLOW`, 명조 큰 제목 「영상을 이해하고, 다음 행동을 설계합니다.」, 설명 한 줄.
- 오른쪽: 목업의 `03 / 03 WORKFLOW STAGES`(장식) 자리에 **오늘 통계 4개**(3절 A2)를 같은 모양(큰 명조 숫자 + 작은 대문자 이름표)으로 둔다. 버전 표기 `V 0.1 — LOCAL`은 남긴다.
- **높이를 줄인다.** 목업은 제목 영역과 흐름 띠가 약 460px을 차지해 1080px 화면에서 3열이 잘린다. 1920×1080에서 3열의 주요 내용이 스크롤 없이 보이도록 제목 글자 크기와 위아래 여백을 줄인다(시연 영상 기준).

### 2.3 흐름 띠

- 모서리 꺾쇠 안의 `01` `02` `03`과 금색에서 흐려지는 선. 목업 그대로.
- 지금 사용자가 있는 단계를 밝게 한다: 영상을 고르기 전에는 01, 고르면 02, 초안이 검사를 통과하면 03.

### 2.4 영상 탐색 (01)

- 탭 2개: 「키워드 검색」「URL 직접 입력」. URL 탭에서는 검색창 안내 문구가 바뀌고 주소 하나를 받아 영상 한 개를 불러온다.
- 검색창 + [영상 찾기 ↗]. **입력 없이 버튼 한 번으로 목록이 떠야 한다**(과제 원문). 처음 열었을 때 기본 검색어(`discover.query`)가 들어 있다.
- 거르기 3개: 업로드 기간(최근 1일·1주·1개월), 정렬 방식(최신순·관련성순·조회수순, 기본 최신순), 표시 개수(10·20).
- 「쇼츠 제외」 체크(2026-11-16 실제 데이터 보정): 거르기 줄 끝에 같은 높이로. 기본 켬(`discover.exclude_shorts`). 결과 줄에 「쇼츠 n개 제외」. 줄이 늘지 않게 한다.
- 「뜨기 직전」 찾기는 10단계에서 거르기 옆 단추로 넣는다.
- 영상 줄: 썸네일(길이 표시) · 제목 · 채널 · 조회수 · 올린 때 · 오른쪽 동그란 선택 표시. 한 번에 하나만 선택. 이미 댓글을 단 영상은 작은 금색 글씨로 표시하고 실행 버튼을 막는다.
- 목업의 「※ 영상 정보는 디자인 시연용 가상 데이터입니다」는 넣지 않는다. 그 자리에 할당량 사용량이나 저장된 결과를 쓴다는 안내를 둔다.

### 2.5 AI 분석과 댓글 초안 (02)

- 선택한 영상 카드(썸네일 · 제목 · 「선택한 영상」).
- 「영상 맥락 분석 / CONTEXT REPORT」: 주요 주제 · 핵심 고민(= 과제의 "고민 한 줄") · 영상 톤 · 시청자 니즈 · 분석 근거. 분석 근거 줄에는 **근거 문장**과 출처(자막·제목·설명·댓글)를 적는다.
- 자막 출처 표시와 「자막 붙여넣기」 입력(접어 둠).
- 분석이 연애 고민을 찾지 못하면(`no_love_concern`) 초안 없이 멈추고, 진행 줄 아래 오류 상자에 「이 영상 자료에서 연애 고민을 찾지 못했습니다」와 다음 행동을 띄우며 「자막 붙여넣기」를 연다. 핵심 고민 줄은 「연애 고민 없음」(2026-11-16 실제 데이터 보정).
- 「댓글 초안」 + 글자 수 `n / 120자` + 고칠 수 있는 글 상자.
- 글 상자 아래: 상태 이름표(`DRAFT · REVIEW REQUIRED` → 검사를 통과하면 `CHECKED`), [다른 초안 생성 ↗].
- **규칙 검사 결과**: 통과·실패 항목(DESIGN 5.4). 실패가 있으면 03의 실행 버튼이 막힌다.
- 목업의 안내 「영상의 구체적 장면은 실제 자막 등 검증 가능한 근거가 있을 때만 반영합니다」는 그대로 둔다. 이 프로젝트의 원칙과 같다.

### 2.6 실행 및 관리 (03)

- 「브라우저 환경 / LOCAL CONTROL」 설정 4줄: 사용 프로필 · 작업 방식 · 일일 제한 · 오늘 작업 `n / 상한 건`.
- 작업 상자: 제목(지금 상태를 한마디로: 「작업 준비 완료」 등) + 설명(「게시 여부는 로그인된 사용자 본인이 결정합니다」) + 큰 버튼 [브라우저에서 영상 열기 ↗] + **진행 단계 표시**(3절 A4) + 실패하면 사유와 화면 캡처 링크.
- `OPERATION NOTE`: 중복 작업 방지 · 활동 이력 기록 · 공개적 홍보 관계 표시. 목업 그대로.

### 2.7 작업 기록

- 열: TIME · VIDEO · ACTION · **COMMENT** · STATUS · PROFILE · 댓글 보기 링크. 최신이 위. `VIEW ALL ↗`로 전체를 연다.
  - 9단계: 열 이름은 한국어(시간 · 영상 · 작업 · 댓글 · 상태 · 프로필) 아래 영어를 작게. 첫 화면 표는 최근 5줄, `전체 보기 VIEW ALL ↗`는 겹침 패널로 전체(최대 200건)를 연다(9절).
- 실패 줄은 사유를 함께 보인다.

## 3. 레퍼런스 이미지에만 있어서 추가하는 것

| 번호 | 추가하는 것 | 레퍼런스에서의 모습 | 목업 모양에 넣는 방법 |
|---|---|---|---|
| A1 | **시스템 상태 3개**: AI (Ollama) · YouTube API · 브라우저 | 사이드바 아래 상자 | 위 줄 오른쪽에 작은 점 + 이름 + 상태 문구 세 개. 실제로 확인한 값만. 정상은 연두, 문제는 붉은 점 |
| A2 | **오늘 통계 4개**: 오늘 처리한 영상 `n / 상한` · 생성한 댓글 초안 · 게시 완료 · 성공률 | 위쪽 통계 카드 | 제목 영역 오른쪽. 큰 명조 숫자 + 작은 이름표 |
| A3 | **작업 방식 두 가지**: 수동 승인 후 게시 (권장) / 자동 게시 (테스트 모드) | 실행 관리의 선택 단추 | 목업의 「사람 검토 후 게시」 옆에 「테스트 페이지 자동 실행」을 추가. 고르면 "통제된 테스트 페이지에서만 실행" 안내 |
| A4 | **진행 단계 표시**: 대기 → 프로필 실행 → 댓글 입력 → 승인 대기 → 게시 완료 → 확인 | 가로로 이어진 동그라미 | 작업 상자 안, 큰 버튼 아래. 가는 선과 작은 점, 지금 단계는 금색. 목업의 한 줄 상태 문구는 그 아래에 남긴다 |
| A5 | **분석 항목 2개**: 영상 톤 · 시청자 니즈 | 분석 요약 표 | 영상 맥락 분석 목록에 두 줄 추가 |
| A6 | **말투 분류**: 공감형 · 조언형 등 | `#공감형` 꼬리표 | 글 상자 아래 작은 글씨. `#`을 붙이지 않고 댓글 본문에도 넣지 않는다 |
| A7 | **조회수** | 영상 카드의 「조회수 82만회」 | 영상 줄의 채널 · 올린 때 사이 |
| A8 | **조회수순 정렬** | 정렬 목록 | 정렬 방식에 추가 |
| A9 | **실제 썸네일** | 영상 사진 | 목업의 그러데이션 자리에 YouTube 썸네일 |
| A10 | **댓글 보기 링크, 상태 이름표** | 작업 기록의 링크 아이콘과 「게시 완료」 | 작업 기록 맨 오른쪽 `↗`, STATUS 열은 금색(진행)·밝은 글씨(완료)·붉은 글씨(실패) |
| A11 | **메뉴: 실행 관리 · 설정** | 사이드바 메뉴 | 위 줄 메뉴에 `EXECUTE` · `SETTINGS` |

레퍼런스에 있지만 **넣지 않는 것**: 사이드바 자체(목업은 위 줄 메뉴), 알림 종과 계정 메뉴(로그인 기능 없음), 「댓글 초안 (3)」 탭(초안은 하나씩 다시 만든다), 계정 이메일 표시.

레퍼런스에도 목업에도 없지만 **과제·설계 때문에 넣는 것**: 규칙 검사 결과, 근거 문장과 출처, 자막 붙여넣기, 작업 기록의 댓글 열, 실패 사유와 화면 캡처, 「승인 대기」 단계.

## 5. 화면에 필요한 API

기존 `/`와 `/api/health`는 그대로 둔다. 아래는 **추가**하는 것이다(단계별로 생긴다).

| 주소 | 쓰는 곳 | 단계 |
|---|---|---|
| `GET /api/status` | 시스템 상태(Ollama·YouTube 키 유무·브라우저). 키 값은 싣지 않는다 | 2단계(YouTube 키), 4·8단계에 항목 추가 |
| `GET /api/stats/today` | 오늘 통계 4개 | 7단계. 그 전에는 0과 `–` |
| `GET /api/videos`, `POST /api/videos/resolve`, `GET /api/videos/{id}` | 01칸 | 2단계 |
| `POST /api/analysis/{video_id}`, 초안 고치기·다시 만들기 | 02칸 | 5·6단계 |
| `GET /api/profiles`, `POST /api/jobs`, `GET /api/jobs/{id}`, `POST /api/jobs/{id}/approve` | 03칸 | 7·8단계 |
| `GET /api/records` | 작업 기록 | 7단계 |
| `GET /api/settings` | SETTINGS 패널(읽기 전용). 키 값·PC 경로·LLM 주소는 싣지 않는다 | 9단계 |
| `POST /api/llm/warmup` | SETTINGS 패널의 [모델 미리 불러오기]. 단추를 누를 때만 부른다 | 4단계 API, 단추는 9단계 |

아직 없는 API에 달린 화면 요소는 꺼진 상태로 두고 "n단계에서 연결"이라고 적는다. 목업의 가상 수치와 영상을 화면에 박아 넣지 않는다.

## 6. 모양

목업 HTML의 `<style>`이 출발점이다. 그대로 옮긴 뒤 아래만 고친다.

- **색 변수(목업 그대로).** 바탕 `#0a0a0a`, 패널 `#111111`, 선 `rgba(255,255,255,.18)`·`.10`, 글자 `#f2f0ec`, 보조 `#b2b0ab`, 금색 `#d1b990`. 정상 점 `#b7c4a7`, 붉은 점 `#9a5149`.
- **흐린 글자를 밝게.** 목업의 가장 흐린 글자 `#777570`은 검정 바탕에서 대비가 약 4:1이고 10px로 쓰여 압축된 시연 영상에서 뭉개진다. `#918e88` 이상으로 올리고, 실패 글씨는 `#d98a7e`처럼 읽히는 붉은색을 쓴다.
- **글자 크기를 한 단계 키운다.** 목업은 본문 13px, 이름표 10px이다. 본문 14px, 이름표 11px 이상으로.
  - 9단계에서 한 번 더 올렸다: 본문·목록 제목 14px, 보조 글자 12px 이상, 가장 작은 이름표 11.5px(CSS에 11.5px 미만이 없다. 테스트가 확인한다).
- **글꼴.** 목업은 `Noto Serif CJK KR`·`Noto Sans CJK KR`을 쓰는데 Windows에는 보통 없다. 없으면 제목이 명조로 안 보인다.
  - 순서: 제목 `'Noto Serif KR','Noto Serif CJK KR','Nanum Myeongjo',Batang,Georgia,serif` / 본문 `'Pretendard','Noto Sans KR','Malgun Gothic','Segoe UI',sans-serif`.
  - 실행 중에 외부에서 내려받지 않는다(오프라인에서도 떠야 한다).
  - **명조 글꼴은 프로그램에 넣었다**(대표 결정, 2026-11-16): `app/static/fonts/NotoSerifKR-Regular-subset.woff2`. Noto Serif KR, SIL OFL 1.1, 굵기 400 하나, 약 1MB. 템플릿에서 `/static/fonts/fonts.css`를 불러오면 `"Noto Serif KR"`로 쓸 수 있다. 굵기가 400뿐이니 제목에 굵은 글씨를 쓰지 않는다(목업도 제목은 전부 400이다). 출처와 라이선스는 `app/static/fonts/README.md`.
  - 본문 글꼴은 넣지 않는다. PC에 있는 글꼴을 위 순서대로 쓴다.
- **모서리.** 둥글리지 않는다(목업은 전부 각진 선). 선택 표시와 점만 둥글다.
- **선.** 카드 대신 가는 선으로 구역을 나눈다. 그림자 없음.
- **아이콘.** 목업처럼 글자 화살표(`↗`)와 CSS 도형만. 아이콘 글꼴이나 외부 CDN을 쓰지 않는다.
- **상태 표시.** 색만으로 구분하지 않는다. 점이나 색 옆에 항상 글자가 있다.
- 밝은 모드는 만들지 않는다.

## 7. 반응형

목업의 기준점을 그대로 쓴다.

| 너비 | 배치 |
|---|---|
| 1121px 이상 | 위 줄 메뉴 + 3열 |
| 751~1120px | 메뉴 숨김(메뉴 단추로), 2열 + 03칸은 아래 전체 너비, 흐름 띠 설명 숨김 |
| 750px 이하 | 한 열로 01→02→03→작업 기록, 흐름 띠는 세로, 작업 기록 표는 가로 스크롤 |

작업 기록 표 말고는 가로 스크롤이 생기지 않아야 한다. 영상 목록이 길면 칸 안에서 세로 스크롤.

- 9단계: 1121px 이상에서 세 칸의 최대 높이를 "창 높이 − 3열 시작 위치"로 둔다(`layout.js`). 내용이 그보다 길면 **그 칸 안에서만** 세로로 스크롤한다. 1920×1080에서는 스크롤 없이 다 들어가고, 프로그램 창 기본 크기(1600×1000)에서는 01칸만 칸 안 스크롤이 생긴다. 남는 높이가 420px보다 작으면 자르지 않고 페이지가 길어진다.
- 9단계: 750px 이하에서 겹침 패널은 화면 너비 − 16px. 전체 기록 패널의 표는 줄마다 카드(칸 이름 + 값)로 바뀐다.

## 8. 구현 방식

- 지금처럼 Jinja 템플릿 + 정적 CSS·JS(바닐라). 빌드 도구와 프레임워크를 넣지 않는다.
- 목업의 CSS를 `app/static/css/`로 옮겨 읽기 좋게 나눈다(한 줄로 붙어 있다). 목업의 `<script>`는 가상 데이터용이라 옮기지 않는다.
- `app/static/js/`: api.js, state.js, 칸별 파일. 화면 상태는 한 곳(`state.js`)에 두고, 칸은 그 상태를 보고 다시 그린다. 선택한 영상이 바뀌면 02·03이 따라 바뀐다.
- 키보드로 탭·목록·버튼을 다룰 수 있게 한다. 목업의 `focus-visible` 금색 테두리를 유지한다. 영상 줄은 `div`가 아니라 누를 수 있는 요소로 만든다.
- 화면 확인용 브라우저 창은 주 모니터에 띄우지 않는다(headless 또는 2번 모니터, AGENTS.md 창 규칙).

## 9. 대시보드 완성 (9단계, 2026-11-17)

처음 보는 사람이 설명 없이 세 칸을 끝까지 쓰게 한다. 큰 틀(검정·금색, 위 줄 메뉴, 흐름 띠, 3열, 아래 작업 기록)은 그대로다.

### 9.1 다음 행동 하나만 강조

- 화면 전체에서 금색으로 채운 단추는 **하나뿐**이다(`.is-next`, `app/static/js/next.js`). 다른 단추는 기본으로 회색 선만 둔다. 목업은 큰 단추를 처음부터 금색·흰색으로 채웠지만, 그러면 어디를 눌러야 할지 한눈에 안 보여 바꿨다.
- 순서: 영상 전 [영상 찾기](URL 탭이면 [불러오기]) → 목록에서 고르기(목록 왼쪽 금색 선) → [분석하고 초안 만들기] → [이 초안 승인] → [브라우저에서 영상 열기] → 승인 대기에서 [게시 승인](실제 유튜브는 [게시했어요]) → 게시 뒤 다른 영상 고르기.
- 규칙 검사에 걸리면 초안 글 상자(금색 테두리), 「연애 고민 없음」이면 자막 붙여넣기 상자. 진행 중(분석·입력)에는 아무것도 강조하지 않는다.
- 흐름 띠의 지금 단계 설명 줄이 같은 안내를 쓴다(「다음 → [이 초안 승인]을 누르세요」). 좁은 화면에서도 지금 단계 안내 줄은 보인다.
- 오래 걸리는 일은 예상 시간을 쓴다: 분석·초안 1~2분, 영상 찾기 1~2초, 모델 미리 불러오기 1~2분.

### 9.2 한국어 이름표

- 메뉴, 시스템 상태(AI 모델 · 유튜브 · 브라우저), 오늘 통계(오늘 처리 · 초안 · 게시 완료 · 성공률), 작업 기록 열, 칸 꼬리표(검토 필요 · 승인됨)는 한국어를 앞(또는 위)에, 영어는 작게.

### 9.3 겹침 패널 두 개

- 브라우저의 `<dialog>`(showModal). 열면 패널 제목으로 초점, Esc·[닫기 ×]·바깥 누르기로 닫고, 닫으면 연 단추로 초점이 돌아온다.
- **SETTINGS(읽기 전용)**: 댓글 규칙(글자 수 · 홍보 표기 · 브랜드 · 브랜드 사실), 운영 한도(하루 상한 · 기본 작업 방식 · 영상당 댓글), 프로필 3개와 폴더 준비 여부, AI 모델(공급자 · 모델 · 로컬/외부), 브라우저(크롬 창 위치와 확인 결과 · 크롬 찾음 · 입력 속도), YouTube(키 있음/없음 · 오늘 할당량). 키 값·PC 경로는 보이지 않는다. 값을 바꾸려면 `config.yaml`·`.env`를 고치고 다시 켠다.
  - [모델 미리 불러오기]: `POST /api/llm/warmup`. 패널을 연다고 부르지 않고 단추를 누를 때만 부른다. 누르면 경과 초를 보이고, 끝나면 걸린 시간 또는 오류와 할 일을 쓴다.
- **VIEW ALL(작업 기록 전체)**: 최근 200건, 실패 사유, 실패 화면 캡처 링크(`/api/jobs/{id}/screenshot`, 앱을 다시 켠 뒤에도 캡처 폴더에서 찾는다), [실패만 보기]. 첫 화면 표는 최근 5줄 그대로.

### 9.4 메뉴

- 메뉴를 누르면 그 칸으로 스크롤하고 칸을 잠깐(1.4초) 밝게 한 뒤 칸 제목에 초점을 둔다.
- 지금 칸을 메뉴에 표시한다(`aria-current`). 넓은 화면에서는 흐름 단계(01·02·03)를 따르고, 작업 기록까지 내려가면 「기록」, 좁은 화면에서는 스크롤 위치를 따른다.

### 9.5 빈 상태·불러오는 중·오류 문구

칸마다 빈 상태, 불러오는 중, 오류 문구에 **다음에 할 일**을 쓴다(예: 「조건에 맞는 영상이 없습니다. 업로드 기간을 넓히거나 검색어를 바꿔 [영상 찾기]를 다시 눌러 보세요.」).

### 9.6 측정(headless 크롬, 가짜 YouTube 12개 영상 + 가짜 LLM)

| 화면 | 3열 끝(px) | 칸 안 스크롤 | 가로 넘침 | 가장 작은 글자 |
|---|---|---|---|---|
| 1920×1080 | 1040 (≤1080) | 없음 | 0 | 11.5px |
| 1600×1000 | 998 (≤1000) | 01칸만 61px | 0 | 11.5px |
| 1000×900 | 2열, 페이지 스크롤 | 없음 | 0 | 11.5px |
| 390×844 | 1열, 페이지 스크롤 | 없음 | 0 | 11.5px |

모든 크기에서 상태마다(처음 · 목록 · 선택 · 초안 · 검사 걸림 · 승인 · 승인 대기 · 게시 완료 · 게시 실패) 금색 강조가 정확히 하나였다. 두 패널은 모든 크기에서 열리고, Esc로 닫으면 연 단추로 초점이 돌아왔다.
