## 1. 대표 지시 (2026-11-16)

- 좌측 사이드바, 상단 통계 카드
- 3열 메인: 영상 탐색 / AI 분석 및 댓글 초안 / 실행 관리
- 카드, 검색, 선택, 상태 표시가 실제로 동작
- 좁은 화면에서는 반응형
- 이미지의 수치는 예시다. 실제 데이터와 연결한다
- 댓글은 광고 관계를 명확히 표시하고 사용자가 최종 검토한다
- 기존 FastAPI 구조와 백엔드 기능 유지. 기존 API를 지우거나 임의로 바꾸지 않는다
- 색과 분위기: 처음에는 다크 모드·보라 포인트였으나, 바꾼 레퍼런스에 맞춰 **밝은 크림 바탕에 브라운 포인트**로 한다

## 2. 화면 구성

```text
┌────────┬──────────────────────────────────────────────────────────────┐
│ 사이드바 │ 작은 영문 표제 + 제목 「유튜브 마케팅 AI 에이전트」 + 꼬리표          │
│        ├──────────────────────────────────────────────────────────────┤
│ 로고    │ 통계 한 줄: 오늘 처리한 영상 │ 생성한 댓글 초안 │ 게시 완료 │ 성공률   │
│ 메뉴 6개 ├──────────────────┬─────────────────────┬─────────────────────┤
│        │ 01 영상 탐색       │ 02 AI 분석 & 댓글 생성 │ 03 실행 관리          │
│        │ 검색창 + 거르기 3개 │ 선택한 영상 카드       │ 게시 설정            │
│        │ 영상 목록(선택)    │ 영상 분석 요약 표      │ 큰 실행 버튼          │
│ 시스템   │                  │ 댓글 초안 + 글자 수    │ 진행 단계 표시        │
│ 상태    │                  │ 규칙 검사 · 다른 초안  │ (실패 사유·화면 캡처)  │
│        ├──────────────────┴─────────────────────┴─────────────────────┤
│        │ 작업 기록 (전체 너비 표)                                        │
└────────┴──────────────────────────────────────────────────────────────┘
```

### 2.1 사이드바

- 로고 「JG Group / Marketing AI Agent」
- 메뉴 6개: 대시보드 · 영상 탐색 · AI 분석·생성 · 실행 관리 · 작업 기록 · 설정. 선택된 메뉴는 옅은 브라운 바탕.
  - 한 화면짜리 앱이다. 영상 탐색·AI 분석·실행 관리·작업 기록은 해당 칸으로 이동(잠깐 강조), 설정은 같은 화면의 패널로 연다. 페이지를 새로 만들지 않는다.
- 아래쪽 「시스템 상태」: AI 모델 (Ollama) · YouTube API · 브라우저 제어 각각 점 + 상태 문구. 실제로 확인한 값만 보인다.

### 2.2 통계 한 줄

카드 네 장이 아니라 **칸막이로 나눈 긴 카드 한 장**이다.

| 칸 | 표시 | 실제 값 |
|---|---|---|
| 오늘 처리한 영상 | `n / 상한` | 오늘 게시 완료 수 / `limits.daily_max_comments` |
| 생성한 댓글 초안 | `n 개` | 오늘 만든 초안 수 |
| 게시 완료 | `n 개` | 오늘 성공 기록 수 |
| 성공률 | `n %` | 오늘 성공 ÷ (성공 + 실패). 기록이 없으면 `–` |

오른쪽 끝의 언덕 무늬는 장식이다. CSS나 인라인 SVG로 옅게 넣고, 없어도 된다.

### 2.3 01 영상 탐색

- 탭은 없다. **검색창 하나가 검색어와 유튜브 링크를 둘 다 받는다.** 입력이 유튜브 주소나 영상 ID 모양이면 그 영상을 바로 불러오고, 아니면 검색한다. 안내 문구: `검색어 또는 유튜브 링크`. (이미지에는 링크 입력이 없지만 가점 항목이라 넣는다.)
- 검색창 옆 둥근 화살표 버튼 = [영상 불러오기]. **입력 없이 버튼 한 번으로 목록이 떠야 한다**(과제 원문). 처음 열었을 때 기본 검색어(`discover.query`)가 들어 있다.
- 거르기 3개: 업로드 기간(최근 1일·1주·1개월), 정렬(최신순·조회수순), 개수(10·20).
- 「뜨기 직전」 찾기는 10단계에서 거르기 옆 단추로 넣는다.
- 영상 카드: 썸네일(길이 표시) · 제목 · 채널 · 조회수 · 올린 때. 한 번에 하나만 선택(브라운 테두리 + 체크). 이미 댓글을 단 영상은 꼬리표로 표시하고 실행 버튼을 막는다.

### 2.4 02 AI 분석 & 댓글 생성

- 맨 위에 **선택한 영상 카드**(썸네일·제목·채널). ①에서 고른 것이 무엇인지 여기서 다시 보인다.
- 영상 분석 요약 표: 주요 주제 · 핵심 고민(= 과제의 "고민 한 줄") · 영상 톤 · 시청자 니즈. 아래에 **근거 문장**과 출처(자막·제목·설명·댓글).
- 자막 출처 표시(붙여넣은 자막 / 제목·설명 대체)와 「자막 붙여넣기」 입력.
- AI 댓글 초안: 본문(고칠 수 있음) + 글자 수 `(92 / 120자)` + [다른 초안 생성].
- **규칙 검사 결과**: 통과·실패 항목을 초안 아래에 표시(DESIGN 5.4). 실패가 있으면 ③의 실행 버튼이 막힌다.
- 말투 꼬리표(공감형 등)는 초안의 말투 분류로만 보인다. `#`을 붙이지 않고, 댓글 본문에도 들어가지 않는다.

### 2.5 03 실행 관리

- 게시 설정
  - 사용 프로필: 유튜브1·2·3 중 선택 또는 자동 배정. 계정 이름·이메일은 보이지 않는다.
  - 게시 방식: 「수동 승인 후 게시 (권장)」/「자동 게시 (테스트 모드)」.
  - 일일 게시 한도: 설정값과 `(오늘 n / 상한)`.
- 큰 실행 버튼 「브라우저로 영상 열기 (댓글 게시)」.
- **진행 단계 표시**(가로로 이어진 동그라미): 대기 → 프로필 실행 → 댓글 입력 → **승인 대기** → 게시 완료 → 확인. 지난 단계는 체크, 지금 단계는 강조, 남은 단계는 흐리게. 이미지에는 다섯 단계지만 사람 승인이 핵심이라 「승인 대기」를 넣는다.
- 단계 표시 아래 빈 자리: 지금 단계 설명 한 줄, 「게시 승인」 버튼(승인 대기일 때), 실패하면 사유와 화면 캡처 링크, 끝나면 「댓글 보기」.

### 2.6 작업 기록 (아래 전체 너비)

- 열: 시간 · 영상 제목 · 사용 프로필 · **댓글(앞부분, 올리면 전체)** · 상태 꼬리표(게시 완료 / 초안 생성 / 실패) · 댓글 보기 링크.
- 이미지에는 댓글 열이 없지만 과제가 "무슨 댓글을" 기록하라고 하므로 넣는다.
- 최신이 위. 실패 줄은 사유를 함께 보인다.

## 4. 화면에 필요한 API

기존 `/`와 `/api/health`는 그대로 둔다. 아래는 **추가**하는 것이다(단계별로 생긴다).

| 주소 | 쓰는 곳 | 단계 |
|---|---|---|
| `GET /api/status` | 사이드바 시스템 상태(Ollama·YouTube 키 유무·브라우저). 키 값은 싣지 않는다 | 2단계(YouTube 키), 4·8단계에 항목 추가 |
| `GET /api/stats/today` | 통계 한 줄 | 7단계. 그 전에는 0과 `–` |
| `GET /api/videos`, `POST /api/videos/resolve`, `GET /api/videos/{id}` | 01칸 | 2단계 |
| `POST /api/analysis/{video_id}`, 초안 고치기·다시 만들기 | 02칸 | 5·6단계 |
| `GET /api/profiles`, `POST /api/jobs`, `GET /api/jobs/{id}`, `POST /api/jobs/{id}/approve` | 03칸 | 7·8단계 |
| `GET /api/records` | 작업 기록 | 7단계 |

아직 없는 API에 달린 화면 요소는 꺼진 상태로 두고 "n단계에서 연결"이라고 적는다. 예시 수치를 화면에 박아 넣지 않는다.

## 5. 모양

- **분위기.** 밝고 따뜻한 종이 느낌. 크림 바탕, 거의 흰 카드, 아주 옅은 테두리와 그림자, 브라운 포인트 하나.
- **색.** 값은 `style.css` 맨 위 변수로 모은다. 아래는 출발점이고 화면에서 보고 다듬는다.

| 쓰임 | 값 |
|---|---|
| 바탕 | `#F6F1EA` |
| 카드 | `#FFFDFA` |
| 테두리 | `#E8DFD4` |
| 본문 글자 | `#2A241F` |
| 설명 글자 | `#6B6158` |
| 포인트(버튼·선택) | `#7A5C46` (누를 때 `#654A38`) |
| 선택 테두리·지금 단계 | `#C58A5C` |
| 옅은 포인트 바탕(선택된 메뉴·카드) | `#F1E7DB` |
| 성공 | `#2E7D4F` |
| 실패 | `#B93C2B` |

- **대비.** 이미지의 옅은 회색 글씨는 그대로 쓰지 않는다. 본문과 설명 글자는 바탕 대비 4.5:1 이상. 시연 영상은 압축되므로 흐린 글씨가 가장 먼저 뭉개진다.
- **글꼴.** `Pretendard`가 있으면 쓰고 없으면 `Malgun Gothic`·`Segoe UI`. 외부 글꼴을 내려받지 않는다(오프라인에서도 떠야 한다).
- **번호.** 칸 제목 앞에 크고 옅은 `01` `02` `03`.
- **카드.** 둥근 모서리 16~20px, 옅은 테두리, 아주 약한 그림자.
- **상태 꼬리표.** 작은 알약 모양, 색 + 글자 + 체크 표시 함께(색만으로 구분하지 않는다).
- **아이콘.** 가는 선 인라인 SVG. 아이콘 글꼴이나 외부 CDN을 쓰지 않는다.
- 어두운 모드는 만들지 않는다.

## 6. 반응형

| 너비 | 배치 |
|---|---|
| 1280px 이상 | 사이드바 + 통계 한 줄 + 3열 + 아래 작업 기록 |
| 900~1279px | 사이드바는 아이콘만, 통계 2×2, 3열 유지(좁으면 03이 아래로) |
| 900px 미만 | 사이드바는 위쪽 메뉴 단추로 접힘, 통계 2×2, 칸은 01→02→03→작업 기록 세로로 |

- 가로 스크롤이 생기지 않아야 한다. 영상 목록만 칸 안에서 세로 스크롤.
- 1920×1080 화면에서 3열이 스크롤 없이 한눈에 보여야 한다(시연 영상 기준). 작업 기록은 아래로 내려가도 된다.

## 7. 구현 방식

- 지금처럼 Jinja 템플릿 + 정적 CSS·JS(바닐라). 빌드 도구와 프레임워크를 넣지 않는다.
- `app/static/` 아래를 `css/`, `js/`(api.js, state.js, 칸별 파일)로 나눈다.
- 화면 상태는 한 곳(`state.js`)에 두고, 칸은 그 상태를 보고 다시 그린다. 선택한 영상이 바뀌면 02·03이 따라 바뀐다.
- 키보드로 목록·버튼을 다룰 수 있게 한다.
- 화면 확인용 브라우저 창은 주 모니터에 띄우지 않는다(headless 또는 2번 모니터, AGENTS.md 창 규칙).
