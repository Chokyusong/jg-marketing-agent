- 작성: 2026-11-16. 대표가 준 디자인 레퍼런스 이미지 한 장을 글로 옮긴 것이다.
- 이미지 원본은 `docs/design/dashboard-reference.png`에 둔다(대표가 파일로 넣어 주면 커밋). 이미지가 없어도 이 문서만으로 만들 수 있게 적었다.
- 구조와 규칙은 [DESIGN.md](DESIGN.md), 단계는 [STAGES.md](STAGES.md)가 기준이다. 이 문서는 화면만 다룬다.

## 1. 대표 지시 (2026-11-16)

- 다크 모드 기반, 보라색 포인트 컬러
- 좌측 사이드바, 상단 통계 카드
- 3열 메인: 영상 탐색 / AI 분석 및 댓글 초안 / 실행 관리
- 카드, 탭, 검색, 선택, 상태 표시가 실제로 동작
- 좁은 화면에서는 반응형
- 이미지의 수치는 예시다. 실제 데이터와 연결한다
- 댓글은 광고 관계를 명확히 표시하고 사용자가 최종 검토한다
- 기존 FastAPI 구조와 백엔드 기능 유지. 기존 API를 지우거나 임의로 바꾸지 않는다

## 2. 화면 구성

```text
┌────────┬──────────────────────────────────────────────────────────────┐
│ 사이드바 │ 제목 「유튜브 마케팅 AI 에이전트」 + 꼬리표 「TRACK 2 · 제이지그룹 과제」 │
│        ├───────────────┬───────────────┬───────────────┬──────────────┤
│ 로고    │ 오늘 처리한 영상 │ 생성한 댓글 초안 │ 게시 완료      │ 성공률        │
│ 메뉴 7개 ├───────────────┴──┬────────────┴────────┬──────┴──────────────┤
│        │ ① 영상 탐색        │ ② AI 분석 · 댓글 생성  │ ③ 실행 관리          │
│        │ 탭: 키워드 / URL   │ 탭: 분석 결과 / 초안(n) │ 게시 설정            │
│ 시스템   │ 검색창 + 거르기 3개 │ 영상 분석 요약 표      │ 큰 실행 버튼          │
│ 상태    │ 영상 목록(선택)    │ 댓글 초안 + 글자 수    │ 진행 상태            │
│ 버전    │                  │ 다른 초안 생성         │ 최근 작업 기록 표      │
└────────┴──────────────────┴─────────────────────┴─────────────────────┘
```

### 2.1 사이드바

- 로고 「JG Marketing AI Agent」
- 메뉴: 대시보드 · 영상 탐색 · AI 분석·생성 · 실행 관리 · 작업 기록 · 계정 관리 · 설정. 선택된 메뉴는 보라색 바탕.
  - 한 화면짜리 앱이다. 영상 탐색·AI 분석·실행 관리는 해당 칸으로 이동(강조), 작업 기록·계정 관리·설정은 같은 화면 안의 패널(또는 겹침 창)로 연다. 페이지를 새로 만들지 않는다.
- 아래쪽 「시스템 상태」: AI (Ollama) · YouTube API · 브라우저 각각 초록 점 + 상태 문구. 실제로 확인한 값만 보인다.
- 맨 아래 버전 표기.

### 2.2 통계 카드 4개

| 카드 | 표시 | 실제 값 |
|---|---|---|
| 오늘 처리한 영상 | `n / 상한` + 진행 막대 + % | 오늘 게시 완료 수 / `limits.daily_max_comments` |
| 생성한 댓글 초안 | `n 개` | 오늘 만든 초안 수 |
| 게시 완료 | `n 개` | 오늘 성공 기록 수 |
| 성공률 | `n %` | 오늘 성공 ÷ (성공 + 실패). 기록이 없으면 `–` |

### 2.3 ① 영상 탐색

- 탭 2개: 「키워드 검색」「URL 직접 입력」.
- 키워드 탭: 검색창(기본값 `discover.query`) + [검색] 버튼. 거르기 3개 — 업로드 기간(최근 1일·1주·1개월), 정렬(최신순·조회수순), 결과 수(10·20).
  - **입력 없이 버튼 한 번으로 목록이 떠야 한다**(과제 원문). 처음 열었을 때 기본 검색어가 들어 있다.
  - 「뜨기 직전」 찾기는 10단계에서 거르기 옆 단추로 넣는다.
- 영상 카드: 썸네일(길이 표시) · 제목 · 채널 · 조회수 · 올린 때. 한 번에 하나만 선택(보라 테두리 + 체크). 이미 댓글을 단 영상은 꼬리표로 표시하고 실행 버튼을 막는다.
- URL 탭: 주소 입력 → [불러오기] → 같은 카드 한 장.

### 2.4 ② AI 분석 · 댓글 생성

- 탭 2개: 「분석 결과」「댓글 초안 (n)」.
- 영상 분석 요약 표: 주요 주제 · 핵심 고민(= 과제의 "고민 한 줄") · 영상 톤 · 시청자 니즈. 아래에 **근거 문장**과 출처(자막·제목·설명·댓글)를 보인다.
- 자막 출처 표시(붙여넣은 자막 / 제목·설명 대체)와 「자막 붙여넣기」 입력.
- 댓글 초안 카드: 본문(고칠 수 있음) + 글자 수 `92 / 120자` + [다른 초안 생성].
- **규칙 검사 결과**: 통과·실패 항목을 초안 아래에 표시(DESIGN 5.4). 실패가 있으면 ③의 승인 버튼이 막힌다.
- 말투 꼬리표(공감형 등)는 초안의 말투 분류로만 보인다. 댓글 본문에는 들어가지 않는다(해시태그 금지).

### 2.5 ③ 실행 관리

- 게시 설정
  - 사용 프로필: 유튜브1·2·3 중 선택 또는 자동 배정.
  - 게시 방식: 「수동 승인 후 게시 (권장)」/「자동 게시 (테스트 모드)」.
  - 일일 게시 한도: 설정값과 `(오늘 n / 상한)`.
- 큰 실행 버튼 「브라우저로 영상 열기 (댓글 게시)」.
- 진행 상태: 프로필 여는 중 → 입력 중 → 승인 대기 → 게시 완료 · 댓글 보기. 실패하면 사유와 화면 캡처 링크.
- 최근 작업 기록 표: 시간 · 영상 제목 · 프로필 · 상태 꼬리표(게시 완료 / 초안 생성 / 실패) + [전체 보기].

## 3. 레퍼런스 이미지와 다르게 만드는 곳

이미지는 화면 모양의 기준이고, 아래 내용은 DESIGN 2절(원문과 다르게 만드는 부분)을 따른다.

| 이미지 | 이 프로젝트 | 이유 |
|---|---|---|
| 초안 예시 "저도 비슷한 고민을 했었는데…" (시청자 말투, 표기 없음) | `[광고]`로 시작하는 홍보 담당자 말투. 표기 부분은 색을 달리해 눈에 띄게 | 광고 관계 표시, 사칭 금지 |
| 사용 계정에 구글 이메일 표시 | 프로필 이름만(유튜브1·2·3) | 시연 영상에 개인 이메일이 찍히지 않게 |
| 자동 게시 (테스트 모드) | `sandbox` 대상. 자동 타이핑·게시·확인은 통제된 테스트 페이지에서만. 선택하면 "테스트 페이지에서 실행" 안내를 띄움 | DESIGN 6.1 |
| 수동 승인 후 게시 (권장) | `assist` 대상. 프로필과 영상을 열고 초안을 복사해 주면 사람이 붙여넣고 게시 | DESIGN 6.1 |
| 일일 한도 20개를 고르는 목록 | 기본 10개(과제 원문). 화면에서는 설정값 이하로만 낮출 수 있음 | 상한은 코드에서 강제 |
| `#공감형` 꼬리표 | 말투 분류 표시. 본문에 넣지 않음 | 해시태그 금지 |
| 알림 종, 계정 메뉴 | 알림은 실패 기록 수 표시로만. 로그인 기능 없음 | 로컬 1인용 앱 |

## 4. 화면에 필요한 API

기존 `/`와 `/api/health`는 그대로 둔다. 아래는 **추가**하는 것이다(단계별로 생긴다).

| 주소 | 쓰는 곳 | 단계 |
|---|---|---|
| `GET /api/status` | 사이드바 시스템 상태(Ollama·YouTube 키·브라우저) | 2단계(YouTube 키), 4·8단계에 항목 추가 |
| `GET /api/stats/today` | 통계 카드 4개 | 7단계. 그 전에는 0과 `–` |
| `GET /api/videos`, `POST /api/videos/resolve`, `GET /api/videos/{id}` | ①칸 | 2단계 |
| `POST /api/analysis/{video_id}`, 초안 고치기·다시 만들기 | ②칸 | 5·6단계 |
| `GET /api/profiles`, `POST /api/jobs`, `GET /api/jobs/{id}`, `POST /api/jobs/{id}/approve` | ③칸 | 7·8단계 |
| `GET /api/records` | 최근 작업 기록 | 7단계 |

아직 없는 API에 달린 화면 요소는 꺼진 상태로 두고 "n단계에서 연결"이라고 적는다. 예시 수치를 화면에 박아 넣지 않는다.

## 5. 모양

- **색.** 바탕은 아주 어두운 남보라, 카드는 한 단계 밝은 남색, 테두리는 옅은 보라빛 회색. 포인트는 보라(#7C5CFF 근처) 한 가지. 성공 초록, 실패 빨강, 진행 중 보라. 색 값은 `style.css` 맨 위 변수로 모은다.
- **글꼴.** `Pretendard`가 있으면 쓰고 없으면 `Malgun Gothic`·`Segoe UI`. 외부 글꼴을 내려받지 않는다(오프라인에서도 떠야 한다).
- **카드.** 둥근 모서리 14~18px, 옅은 테두리. 칸 제목 앞에 ①②③ 번호.
- **상태 꼬리표.** 작은 알약 모양, 색 + 글자 함께(색만으로 구분하지 않는다).
- **아이콘.** 인라인 SVG. 아이콘 글꼴이나 외부 CDN을 쓰지 않는다.

## 6. 반응형

| 너비 | 배치 |
|---|---|
| 1280px 이상 | 사이드바 + 통계 4칸 + 3열 |
| 900~1279px | 사이드바는 아이콘만, 통계 2×2, 3열 유지(좁으면 ③이 아래로) |
| 900px 미만 | 사이드바는 위쪽 메뉴 단추로 접힘, 통계 2×2, 칸은 ①→②→③ 세로로 |

가로 스크롤이 생기지 않아야 한다. 영상 목록만 칸 안에서 세로 스크롤.

## 7. 구현 방식

- 지금처럼 Jinja 템플릿 + 정적 CSS·JS(바닐라). 빌드 도구와 프레임워크를 넣지 않는다.
- `app/static/` 아래를 `css/`, `js/`(api.js, state.js, 칸별 파일)로 나눈다.
- 화면 상태는 한 곳(`state.js`)에 두고, 칸은 그 상태를 보고 다시 그린다. 선택한 영상이 바뀌면 ②③이 따라 바뀐다.
- 키보드로 탭·목록·버튼을 다룰 수 있게 하고, 탭에는 `role="tablist"`를 단다.
- 화면 확인용 브라우저 창은 주 모니터에 띄우지 않는다(headless 또는 2번 모니터, AGENTS.md 창 규칙).
