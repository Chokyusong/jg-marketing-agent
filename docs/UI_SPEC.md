# 화면 기준 — 프로그램형 화면 (4판)

- 작성: 2026-11-17, 기획 담당(Fable 5.2). 3판(검정·금색 에디토리얼 목업을 그대로 옮긴 화면)을 대체한다.
- 대표 지시(2026-11-17): "프로그램에 알맞게 디자인을 바꿔라. 실제 사용자가 사용하기 쉽게. 설정은 `.env`가 아니라 프로그램 안에서 전부. 테스트가 아니라 실제 게시. 프로필 로그인도 프로그램에서."
- 이 문서는 화면의 구조·모양·문구 원칙을 정한다. 기능의 구현 순서는 [PLAYBOOK.md](PLAYBOOK.md)의 "프로그램화 2차(R1~R3)"에 있다.
- 색은 지금의 검정 바탕·금색 포인트를 이어 쓴다(`docs/design/`의 목업은 색과 분위기의 참고로만 남는다). 구조는 이 문서를 따른다.

## 0. 과제 PDF와 맞춘 것 (2026-11-17 대조)

화면의 이름과 흐름은 과제 PDF를 그대로 따른다. 대조에서 어긋났던 것을 고쳤다.

| PDF | 이 화면 |
|---|---|
| 세 칸: ① 영상 불러오기 → ② 영상 선택 → ③ 댓글 달기 | 작업 화면의 세 칸 이름을 그대로 쓴다 |
| "[영상 불러오기]를 누르면 최신 영상이 썸네일·제목·채널·올린 날짜로" | 단추 이름 [영상 불러오기]. 올린 날짜를 날짜로 보인다(몇 시간 전은 곁들임) |
| "목록에서 영상을 고르면 고민 한 줄과 댓글 초안이 보입니다" | 고르면 **자동으로** 분석하고 초안을 만든다. 따로 누르는 단추가 없다 |
| "[댓글 달기]를 누르면 프로필이 열리고 … 타이핑 → 게시 → 확인" | [댓글 달기] **한 번**으로 끝까지 간다. 따로 승인하는 단추가 없다 |
| 진행 상태 "프로필 여는 중 → 입력 중 → 게시 완료 · 댓글 보기" | 같은 말을 쓴다 |
| 가점: 링크 직접 입력 | ①칸에 눈에 보이는 「영상 링크로 불러오기」 칸 |
| 가점: 유튜브1~3 고르기 또는 자동 배정 | ③칸의 프로필 고르기(자동 배정 포함) |
| 가점: 뜨기 직전 영상 찾기(초안까지만) | ①칸의 [뜨기 직전 영상] 단추 |
| "AI가 자막(없으면 제목·설명)과 인기 댓글을 읽고" | 자막을 자동으로 읽는다. 못 읽으면 제목·설명으로 |

PDF에 없지만 두는 것: 광고 표기 켬/끔(대표 결정), 연습 모드, 기록·프로필·설정 화면, 규칙 검사 결과 표시.

## 1. 원칙 — 실제 사용자가 쉽게

1. **웹페이지가 아니라 프로그램이다.** 큰 구호 문구, 장식용 영문 이름표, 긴 소개 글을 두지 않는다. 창을 열면 바로 일하는 화면이 나온다.
2. **스크롤 없이 한 화면.** 창을 최대화하든 기본 크기든 화면 전체가 스크롤되지 않는다. 길어지는 것(영상 목록, 기록 표)만 자기 자리 안에서 스크롤한다.
3. **다음에 할 일은 하나.** 지금 누를 단추 하나만 금색으로 채운다. 나머지 단추는 테두리만. 금색이 되는 것은 차례로 [영상 불러오기] → (목록에서 고르기) → [댓글 달기] 둘뿐이다.
4. **설정 파일을 열 일이 없다.** API 키, AI 모델, 댓글 규칙, 하루 상한, 프로필 로그인까지 전부 프로그램 안에서 한다.
5. **쉬운 한국어.** 화면 글은 한국어로만 쓴다. 개발 용어(sandbox, assist, target, config, env, API 단위 등)를 쓰지 않는다. 오류에는 "무엇이 잘못됐고 무엇을 누르면 되는지"를 적는다.
6. **처음 켠 사람을 안내한다.** 준비가 안 된 것(유튜브 키, AI 모델, 프로필 로그인)이 있으면 처음 화면에서 차례로 알려 주고 그 자리에서 해결하게 한다.
7. **읽히는 크기.** 본문 15px, 보조 글 13px, 가장 작은 글 12px. 단추와 입력 칸 높이 36px 이상.

## 2. 전체 틀

```text
┌───────┬──────────────────────────────────────────────────────────────┐
│ 왼쪽 줄 │ 위 줄: 화면 이름 · 진행 단계(① 영상 → ② 댓글 → ③ 게시) · 다음 할 일 안내   │
│  JG   ├──────────────────────────────────────────────────────────────┤
│ 작업   │                                                              │
│ 기록   │   화면 내용 (작업 / 기록 / 프로필 / 설정) — 남는 높이 전부           │
│ 프로필  │                                                              │
│ 설정   │                                                              │
│       ├──────────────────────────────────────────────────────────────┤
│       │ 아래 줄: AI 모델 · 유튜브 연결 · 프로필 로그인 · 오늘 게시 n/상한      │
└───────┴──────────────────────────────────────────────────────────────┘
```

- **왼쪽 줄**(폭 76px 안팎): 로고 `JG`, 그 아래 화면 네 개 — 작업 · 기록 · 프로필 · 설정. 아이콘 + 한글 이름. 지금 화면은 금색 표시. 준비가 안 된 화면(예: 프로필에 로그인한 것이 없음)에는 작은 붉은 점.
- **위 줄**(높이 56px 안팎): 지금 화면의 이름. 작업 화면에서는 진행 단계 세 개와 "다음: ○○를 누르세요" 한 줄.
- **아래 줄**(높이 32px 안팎): 상태 네 가지를 점 + 짧은 글로. 누르면 해당 설정 화면으로 간다. 맨 오른쪽에 버전.
- 화면 네 개는 페이지를 새로 여는 것이 아니라 같은 창 안에서 바뀐다. 작업 화면에서 하던 일(고른 영상, 초안, 진행 중인 게시)은 다른 화면에 갔다 와도 그대로 남는다.
- 큰 구호("영상을 이해하고…"), `INTELLIGENT CONTENT WORKFLOW`, 흐름 띠의 꺾쇠 장식, `01 / 03` 같은 번호, 영문 대문자 이름표는 없앤다.

## 3. 작업 화면 (기본 화면)

세 칸이 가로로 나란히. 칸마다 맨 위에 번호와 이름이 고정된 머리가 있다.

| 칸 | 내용 |
|---|---|
| **① 영상 불러오기** | 큰 단추 [영상 불러오기](입력 없이 한 번 누르면 최신 영상 목록). 그 옆에 검색어 칸(기본 검색어가 들어 있다)과 한 줄 거르기: 기간 · 정렬 · 개수 · 쇼츠 빼기. [뜨기 직전 영상] 단추. 그 아래 「영상 링크로 불러오기」 칸 + [불러오기](가점 항목이라 눈에 보이게 따로 둔다). 영상 목록(썸네일 · 제목 · 채널 · **올린 날짜** · 조회수)은 이 칸의 남는 높이를 채우고 여기서만 스크롤한다. 이미 댓글을 단 영상은 「댓글 달았음」 표시 |
| **② 영상 선택** | ①에서 영상을 고르면 **자동으로** 채워진다(단추를 누르지 않는다): 고른 영상 한 줄 요약 → 「영상 속 고민 한 줄」과 근거 문장 → 「댓글 초안」 글 상자 + 글자 수. 만드는 동안 진행 표시(자막 읽는 중 → 고민 정리 중 → 댓글 쓰는 중). 다른 영상을 고르면 하던 것은 버리고 새로 한다. 이미 만든 영상은 바로 보인다. 「광고 표기 붙이기」 켬/끔. 규칙 검사 결과(통과면 한 줄, 걸린 것만 펼침). [다른 댓글 만들기]. 사람이 고칠 수 있다. 자막은 자동으로 읽고, 못 읽었을 때만 「자막 직접 넣기」를 접어서 보인다 |
| **③ 댓글 달기** | 어느 프로필로 올릴지(유튜브1·2·3 또는 자동 배정, 로그인 여부). 큰 단추 [댓글 달기] — **한 번 누르면** 프로필이 열리고 한 글자씩 입력하고 게시하고 내 댓글을 확인하는 데까지 간다(화면에 보이는 초안이 규칙 검사를 통과했을 때만 눌린다). 진행 상태: 프로필 여는 중 → 입력 중 → 게시 완료 · [댓글 보기]. 실패하면 이유와 [화면 캡처 보기] · [다시 시도]. 그 아래 「기록」 3~5줄(시간 · 영상 · 프로필 · 댓글 · 성공/실패)과 [기록 전체 보기] |

- 칸 너비 비율은 대략 30 : 38 : 32. 창이 넓으면 가운데 칸이 더 넓어진다.
- 1920×1009(최대화)와 1600×960(기본 창)에서 세 칸의 내용이 스크롤 없이 다 보인다. 넘치는 것은 ①의 영상 목록뿐.
- 「연습 모드」: ③의 작은 스위치. 켜면 실제 유튜브가 아니라 프로그램 안의 연습 페이지에 댓글을 단다(처음 써 보는 사람과 시연용). 기본은 꺼짐(실제 게시).

## 4. 기록 화면

- 맨 위에 오늘 숫자 네 개: 오늘 게시 n/상한 · 만든 댓글 · 게시 완료 · 성공률.
- 표: 시간 · 영상 · 프로필 · 댓글 · 결과. 거르기: 전체 / 게시 / 실패. 실패 줄에는 이유와 [화면 캡처]. 게시 줄에는 [유튜브에서 보기].
- 표만 스크롤한다.

## 5. 프로필 화면

- 프로필 카드 세 장(유튜브1 · 유튜브2 · 유튜브3). 카드마다: 이름, 로그인 여부(로그인됨이면 채널 이름), 마지막으로 쓴 때.
- [로그인하기]: 그 프로필 전용 크롬 창이 유튜브 로그인 화면으로 열린다. 사용자가 직접 구글 계정으로 로그인하고 창을 닫으면 프로그램이 로그인 여부를 다시 확인한다. 프로그램은 아이디와 비밀번호를 받거나 저장하지 않는다.
- [로그인 확인] · [유튜브 열기] · [로그아웃 안내].
- 맨 위 설명 두 줄: 프로필이 무엇이고 왜 필요한지(유튜브에 댓글을 달 계정), 필수는 유튜브1 하나.

## 6. 설정 화면

왼쪽에 묶음 이름, 오른쪽에 입력 칸. 바꾸면 [저장]이 금색이 되고, 저장하면 바로 적용된다(프로그램을 다시 켤 필요가 없게).

| 묶음 | 항목 |
|---|---|
| 유튜브 연결 | 유튜브 API 키 입력 칸(입력한 뒤에는 「저장됨」으로만 보이고 값은 다시 보여 주지 않는다. [바꾸기] · [지우기]). [연결 확인] 단추와 결과. 키를 받는 방법 안내(접힘). 오늘 사용량 |
| AI | 글 쓰는 AI 고르기(아래 6.1). 고른 AI의 모델, 준비 상태, [연결 확인] |
| 댓글 규칙 | 글자 수 최소·최대, 홍보하는 곳 이름, 그곳에 대해 써도 되는 사실 문장들, 광고 표기 문구, 광고 표기 기본값(켬/끔) |
| 게시 | 하루에 올릴 수 있는 댓글 수, 게시 직전에 한 번 더 확인할지(기본 끔 — 과제는 한 번 누르면 게시까지), 글자 입력 속도, 크롬 창을 띄울 화면(모니터 고르기) |
| 영상 찾기 | 기본 검색어, 기본 개수, 쇼츠 빼기와 쇼츠로 볼 길이 |

- 값이 잘못되면 그 칸 아래에 이유를 적는다. [기본값으로] 단추.
- 비밀값(API 키)은 화면·기록·응답 어디에도 다시 나오지 않는다.

### 6.1 「AI」 묶음 — 글 쓰는 AI 고르기 (R5, 2026-11-17)

왼쪽에 고르는 목록, 오른쪽에 고른 항목의 준비 칸. 묶음 안에서 끝나고 화면 전체 스크롤은 생기지 않는다(목록이 길면 목록만 스크롤).

```text
┌ 글 쓰는 AI ───────────────┬ Claude (API 키) ──────────────────────────┐
│ 이 PC에서                 │ ● 외부 · 영상 자료가 이 회사로 전송됩니다 │
│  ○ Ollama        ● 준비됨 │                                            │
│ API 키로                  │ API 키   [ 저장됨 ]  [바꾸기] [지우기]     │
│  ○ OpenAI        ○ 키 없음│ 모델     [ 목록에서 고르기 ▾ ]             │
│  ◉ Claude        ● 준비됨 │ [연결 확인]   ● 연결됨                     │
│  ○ Gemini        ○ 키 없음│                                            │
│  ○ Grok          ○ 키 없음│ 키 받는 방법 ▸ (접힘)                      │
│  ○ 직접 입력     ○ 주소 없음│                                          │
│ 로그인된 프로그램으로     │                                            │
│  ○ Codex         ● 설치됨 │                                            │
│  ○ Claude Code   ● 설치됨 │                                            │
│  ○ Gemini CLI    설치 안 됨│                                           │
└───────────────────────────┴────────────────────────────────────────────┘
```

- **목록**: 묶음 이름 세 개(「이 PC에서」「API 키로」「로그인된 프로그램으로」) 아래에 항목. 줄마다 이름과 준비 상태(점 + 글자). 지금 쓰는 항목에는 「사용 중」 표시. 설치되지 않은 프로그램은 흐리게, 고를 수 없음.
- **줄을 누르면** 오른쪽에 그 항목의 준비 칸이 보인다(아직 바꾸지는 않는다). 바꾸는 것은 [이 AI 쓰기]를 누르고 [저장]할 때다.
- **오른쪽 칸** (종류마다):
  - Ollama: 지금 있는 것 그대로(모델 고르기, [미리 불러오기], 상태와 해결 방법, 추천 모델 안내).
  - API 키: 키 입력(저장 뒤에는 「저장됨」만, [바꾸기]·[지우기]), 모델 고르기(받아 온 목록 + 직접 적기), [연결 확인]과 결과, 키 받는 방법(접힘). 「직접 입력」은 주소 칸이 하나 더 있다.
  - 로그인된 프로그램: 설치 여부와 버전, 로그인 방법 한 줄 안내(그 프로그램에서 로그인), 모델(선택), [연결 확인]. 「이 프로그램이 저장한 로그인 정보는 읽지 않고, 프로그램을 대신 실행합니다」 한 줄.
- **외부 알림**: 이 PC 밖의 AI는 오른쪽 칸 맨 위에 「외부 · 영상 제목·설명·자막·댓글이 ○○(으)로 전송됩니다. 요금이 들 수 있습니다」를 늘 보인다. [이 AI 쓰기]를 누르면 같은 글로 한 번 확인한다([쓰기] / [취소]).
- **준비가 안 된 AI를 고르면** [이 AI 쓰기]가 흐려지고 이유를 옆에 적는다(「API 키를 먼저 넣어 주세요」).
- **아래 줄·위 줄**: `AI · Claude · 모델 이름 · 외부` 꼴. 이 PC의 AI면 `이 PC`.
- 낱말: 화면에는 「LLM」「공급자」「CLI」를 쓰지 않는다. 「AI」「API 키로」「로그인된 프로그램으로」.

## 7. 처음 켰을 때

준비가 안 된 것이 있으면 작업 화면 위에 「시작 준비」 상자가 뜬다. 세 줄, 줄마다 상태와 단추.

1. 유튜브 연결 — [API 키 넣기]
2. AI 모델 — [모델 확인]
3. 프로필 로그인 — [유튜브1 로그인]

셋 다 되면 상자는 사라진다. 일부만 돼도 닫고 쓸 수 있다(연습 모드는 키와 로그인 없이도 된다는 안내 포함).

## 8. 모양

- **색**: 바탕 `#0b0b0c`, 칸 바탕 `#141416`, 띠·입력 바탕 `#1b1b1e`, 선 `#2a2a2e`, 글자 `#f1efea`, 보조 글 `#a8a59e`, 금색 포인트 `#d1b990`(채운 단추의 글자는 검정), 성공 `#8fbf8f`, 실패 `#e08b7f`, 주의 `#e0c27a`. 색 값은 CSS 변수로 한곳에.
- **글꼴**: 화면 글은 고딕(`Pretendard`, `Malgun Gothic`, `Segoe UI`). 명조(넣어 둔 Noto Serif KR)는 로고와 화면 이름에만.
- **단추**: 채운 단추(다음 할 일, 금색) / 테두리 단추(그 밖) / 글자 단추(덜 중요한 것). 모서리 6px. 누를 수 없을 때는 흐리게 하고 이유를 옆이나 말풍선에.
- **입력 칸**: 이름표가 위에, 높이 36px 이상, 초점이 가면 금색 테두리.
- **칸**: 바탕색 차이와 가는 선으로 구분. 모서리 8px. 그림자 없음.
- **상태 표시**: 점 + 글자. 색만으로 구분하지 않는다.
- **아이콘**: 인라인 SVG 선 아이콘. 외부 글꼴·CDN 없음.
- 영상 제목 뒤의 `#태그`는 흐리게 보인다(제목 원문은 그대로 두고 표시만 나눈다).

## 9. 크기별 배치

| 화면 안쪽 크기 | 배치 |
|---|---|
| 1920×1009 (1080 모니터에서 최대화) | 전체 틀 + 세 칸. 화면 스크롤 없음 |
| 1600×960 (기본 창) | 같음. 화면 스크롤 없음 |
| 1366×720 | 같음. 칸 안쪽 스크롤 허용 |
| 폭 1100px 아래 | 왼쪽 줄은 아이콘만, 세 칸은 탭으로 하나씩(① ② ③). 화면 스크롤 없음 |

가장 작은 글자는 어느 크기에서도 12px 이상.

## 10. 구현

- 지금처럼 Jinja 템플릿 + 정적 CSS·JS(바닐라). 빌드 도구·프레임워크 없음. 외부 글꼴·아이콘·CDN 없음.
- 화면 네 개는 한 페이지 안의 구역으로 두고 보이기/숨기기로 바꾼다. 상태는 `state.js` 한곳.
- 3판의 "다음 할 일 하나만 금색"(`next.js`), 겹침 패널의 Esc·초점 처리, 키보드 조작은 이어 간다.
- 요소의 `id`를 바꿔야 하면 테스트와 JS를 함께 고친다. 기존 API는 그대로 쓰고, 설정 저장·프로필 로그인 등 새 API는 PLAYBOOK R2·R3에서 더한다.
- 화면 확인은 headless로 한다. 창을 주 모니터에 띄우지 않는다.

## 부록 A. R1 전 지금 화면(3판 구현)의 한 화면 배치 (2026-11-17)

R1(4판 화면)이 들어오기 전까지 쓰는 지금 화면(위 줄 메뉴 · 제목 영역 · 흐름 띠 · 3열 · 작업 기록)을 4판 2절의 "스크롤 없이 한 화면"에 먼저 맞췄다. 대표가 1080 모니터에서 최대화한 프로그램 창을 찍어 "전체 화면에서 스크롤 없이 딱 보이게"를 요청했다. 그 화면에서는 3판 기준(1920×1080 안쪽)으로 맞춘 탓에 페이지 스크롤, 01칸 스크롤 + 목록 스크롤의 이중 스크롤, 01칸 제목 잘림, 작업 기록이 화면 밖인 문제가 있었다. R1에서 이 틀은 4판으로 바뀐다.

- **높이 기준**: 1920×1009(1080 모니터에서 최대화한 창의 실제 화면. 창 제목 줄과 작업 표시줄을 뺀 높이)와 1600×960(기본 창 1600×1000의 안쪽)에서 페이지 세로·가로 스크롤 없음. 1366×720도 페이지 스크롤 없음(칸 안쪽 스크롤은 허용). 폭 1121px 미만은 예전처럼 세로로 쌓고 페이지 스크롤.
- **틀**: 넓은 화면(폭 1121px 이상, 높이 600px 이상)은 창 높이 100% 격자. 위 줄 / 제목 영역 / 흐름 띠 / 3열(남는 높이 전부) / 작업 기록 띠. `body`는 스크롤하지 않는다. 9단계의 `layout.js` 칸 높이 계산(`--col-max`)은 CSS 격자로 바꿨다.
- **위쪽 150px 안쪽**(측정 147px): 제목 영역은 표제·제목 한 줄 + 설명 한 줄, 오늘 통계 4개는 숫자 옆에 이름표를 두고 한 줄. 흐름 띠는 꺾쇠를 작게 하고 지금 단계의 「다음 → [무엇]」 안내 줄은 남겼다. 1500px 이하에서는 장식 표제와 통계 영어 이름표를 숨긴다.
- **3열**: 칸 제목은 칸 맨 위에 고정, 내용은 칸 몸통(`.col-body`) 안에서만 넘친다. 01칸은 영상 목록 한 곳만 스크롤한다. 02칸은 선택한 영상 카드의 「올린 때」와 [YouTube에서 보기]를 한 줄, 자막 출처와 인기 댓글을 한 줄(말줄임, 전체는 마우스를 올리면)로 줄였다.
- **작업 기록 띠**: 3열 아래 높이 고정. 왼쪽에 제목·[전체 보기], 오른쪽에 최근 3줄(시간 · 영상 · 작업 · 댓글 · 상태 · 프로필). 전체는 VIEW ALL 패널. 넓은 화면에서 맨 아래 줄(`JG MARKETING AGENT` · 버전)은 숨긴다(버전은 제목 영역 오른쪽에 있다).
- **넓이와 글자**: 좌우 여백 1600px 이상 40px, 그 아래 28px(최대 폭 제한 없음). 1600px 이상에서 글자 한 단계 더 — 본문 15px, 목록 제목 15px, 보조 글 13px. 가장 작은 글자는 3판대로 11.5px(4판의 12px는 R1에서).
- **영상 줄**: 썸네일 90×51, 위아래 여백을 줄였다. 제목은 두 줄 넘으면 말줄임, 끝에 줄줄이 붙은 `#태그`는 흐리게(`format.js` `titleNode`). 제목 원문은 그대로(`title` 속성·접근성 이름), 제목이 태그뿐이면 나누지 않는다.
- **「쇼츠 제외」 기본값**: 서버는 `discover.exclude_shorts`대로 `checked`를 그리고 있었다. 창을 새로 고칠 때 브라우저가 앞서 바꾼 체크를 되살릴 수 있어 폼 자동 복원을 끄고(`autocomplete="off"`), 시작할 때 HTML의 처음 값으로 되돌린다.
