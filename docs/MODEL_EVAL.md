# 모델 시험 기록

- 이 문서는 LLM 모델을 시험한 결과를 날짜별로 쌓는다. 모델 확정(결정 D3)은 5단계 끝, 초안 규칙 통과율 비교(`scripts/eval_drafts.py`)를 보고 한다.
- 4단계 시험은 **"JSON 통로가 되는가"**만 본다: 한국어 질문 하나에 정해진 모양의 JSON으로 답하는지, 얼마나 걸리는지. 초안 품질은 재지 않는다.

## 4단계 — Ollama 통로 시험 (2026-11-16)

**환경.** Windows 11, NVIDIA GeForce RTX 4070 SUPER(그래픽 메모리 12GB), Ollama 0.34.0(`127.0.0.1:11434`). 이 앱의 `OllamaClient`로 불렀다(`/api/chat`, `stream: false`, `format`에 JSON 스키마, `num_ctx` 8192, `temperature` 0.2, `num_predict` 300).

**방법.** `scripts/ollama_smoke.py --timeout 300` (요청 하나마다 300초 제한). 시작할 때 떠 있던 모델을 모두 내리고, 모델마다 ① 불러오기(빈 `messages`) → ② 같은 질문 두 번(첫 답, 두 번째 답) → ③ 내리기(`keep_alive: 0`). 큰 모델 둘이 그래픽 메모리에 같이 올라가지 않게 하나씩 돌렸다.

**질문.** 짧은 가짜 영상 자료(제목·자막 세 문장·인기 댓글 둘, 연락이 줄어든 애인 이야기)를 주고 `{"concern": 고민 한 줄, "quote": 자료에서 그대로 고른 근거 문장}`을 요구했다.

**대상.** 설치된 모델 중 코드용(`qwen36-code:latest`, `qwen38-code:latest`)을 뺀 넷. 작업 지시의 세 모델(`qwen2.5:7b`, `qwen3.8:27b`, `qwen3.6:latest`)에 더해, 이 PC에 함께 설치돼 있던 `qwen2.5:3b`도 스크립트 기본값(설치된 일반 모델 전부)대로 돌았다.

**결과.** 시간 단위는 초. 불러오기 = 차가운 상태에서 모델을 메모리에 올리는 시간.

| 모델 | 크기 | 생각 끄기 | 불러오기 | 첫 답 | 두 번째 답 | JSON | 한국어 | 근거가 자료에 그대로 있음 | 고민 한 줄 (모델 답) |
|---|---:|---|---:|---:|---:|---|---|---|---|
| `qwen2.5:7b` | 4.7GB | 해당 없음 | 4.3 | 3.7 | 1.2 | 예 | 예 | 아니오 | 애인이 답장을 줄이고 바쁘다는 말만 하기 시작하면서, 그 이유가 집착 때문인지 마음이 식었는지 고민 중 |
| `qwen3.8:27b` | 17.7GB | `think: false` | 31.9 | 30.4 | 5.7 | 예 | 예 | 예 | 연락이 줄어든 애인이 정말로 마음이 식은 것인지, 아니면 단순히 바쁜 것인지 판단할 수 없어 고민하고 있습니다. |
| `qwen3.6:latest` | 23.9GB | `think: false` | 34.8 | 31.7 | 1.2 | 예 | 예 | 예 | 연락이 줄어든 애인이 마음을 식었는지, 아니면 내가 너무 집착하는 것인지 고민하고 있다. |
| `qwen2.5:3b` | 1.9GB | 해당 없음 | 3.4 | 2.6 | 0.4 | 예 | 예 | 예 | 연락이 줄어들어 애인이 마음을 잃지 않았는지 고민하는 시청자 |

- 네 모델 모두 시간 제한 안에 JSON으로 답했고, 첫 시도에서 스키마에 맞았다(다시 시키기 없음). 시간 초과 없음.
- 생각 기능이 있는 두 모델(`/api/show`의 `capabilities`에 `thinking`)에는 `think: false`를 실었고, 답(`message.content`)이 JSON으로 왔다.
- 큰 모델 둘은 불러오기 30초대에 더해 **불러온 직후의 첫 답도 30초쯤** 걸렸다. 두 번째 답부터는 빨라진다(`qwen3.6:latest` 1.2초, `qwen3.8:27b` 5.7초). 시연 전에는 `POST /api/llm/warmup`으로 불러 두고 한 번 답을 시켜 두는 편이 좋다(5단계·9단계에서 반영).
- `qwen2.5:7b`는 근거 문장을 자료에서 그대로 옮기지 않고 고쳐 썼다. 5단계의 근거 문장 검사(V6, 자료에 실제로 있어야 함)에서 걸릴 수 있는 버릇이다. 한 번 시험이라 결론은 아니다 — 5단계 비교에서 다시 본다.
- 이 숫자는 한 번 잰 값이다. 같은 PC에서도 다른 프로그램이 그래픽 메모리를 쓰면 달라진다.

**다시 재는 법**

```powershell
.\.venv\Scripts\python.exe scripts\ollama_smoke.py                       # 설치된 일반 모델 전부
.\.venv\Scripts\python.exe scripts\ollama_smoke.py --models qwen2.5:7b   # 골라서
```

## 5단계 — 초안 규칙 통과율 비교와 모델 결정 D3 (2026-11-16)

- 실행: `.\.venv\Scripts\python.exe scripts\eval_drafts.py` (이 PC, Ollama 0.34.0, 그래픽 메모리 12GB). 가상 맥락 5개(`tests/fixtures/contexts/`: 권태기·짝사랑·재회·부모 반대·질투, 모두 지어낸 자료) × 모델 3개 × 초안 3개. 한 번에 한 모델만 불러 두고 끝나면 내린다(`keep_alive: 0`). 앱과 같은 길(`DraftService`: 분석 → 근거 대조 → 초안 → 규칙 검사 → 걸리면 최대 3번)을 그대로 탄다. YouTube는 가짜 응답, 자막은 붙여 넣은 것으로 넣는다. 전체 7.6분이라 줄이지 않았다(1시간 넘으면 3×2로 줄이기로 했었다).
- 「첫 시도 통과율」은 다시 쓰기 없이 처음 쓴 초안이 V1~V11을 모두 통과한 비율, 「3번 안 통과율」은 걸린 항목을 알려 주고 다시 쓰게 해서 3번 안에 통과한 비율. 시간은 이미 불러 둔 모델 기준이고, 불러오기와 불러온 직후 첫 분석은 따로 적었다.
- 비교 기준(D3 기본값): 3번 안 통과율이 가장 높은 것 → 같으면 첫 시도 통과율 → 같으면 빠른 것.
