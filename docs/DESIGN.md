## 1. 과제 원문 요구사항 (요약)

**미션.** 지정된 영상의 내용과 맥락에 맞는 댓글을 달고, 읽은 사람이 '운명원'에서 연애 사주를 보고 싶게 한다.

**형태.** 지원자 PC에서 실행하는 대시보드. 화면은 세 칸. 원문: "웹에 올린 페이지는 크롬 프로필을 열 수 없으므로, 프로그램은 내 컴퓨터에서 실행하는 방식으로 만들어 주세요." → 이 프로젝트는 더블클릭으로 뜨는 자체 창 프로그램으로 만든다(PLAYBOOK P단계). 안쪽은 로컬 FastAPI 서버와 웹 화면이다.

| 칸 | 원문 요구 |
|---|---|
| ① 영상 불러오기 | 버튼 한 번에 최신 영상이 썸네일·제목·채널·올린 날짜로 뜬다 |
| ② 영상 선택 | 목록에서 고르면 "영상 속 고민 한 줄"과 "댓글 초안"이 보인다. (가점: 링크 직접 입력) |
| ③ 댓글 달기 | 크롬 프로필이 열리고 댓글 창 → 한 글자씩 타이핑 → 게시 → 내 댓글 확인. 진행 상태 표시, 실패 시 이유와 화면 캡처 |

**댓글 조건.** AI가 자막(없으면 제목·설명)과 인기 댓글을 읽고 연애 고민을 먼저 정리한다. 40~120자, 영상 속 구체적 장면이나 말을 하나 이상 언급, 영상마다 다르게. 금지: 링크, 해시태그, 운명원을 직접 이용한 것처럼 지어낸 후기.

**운영 규칙(코드에서 강제).** 영상당 댓글 1개, 하루 게시 상한(기본 10개), 기록(어느 영상·어느 프로필·무슨 댓글·성공/실패, 시간순).

**설정 예시.**

```yaml
profiles: [유튜브1, 유튜브2, 유튜브3]
comment: { min_chars: 40, max_chars: 120, brand: 운명원 }
limits:  { daily_max_comments: 10 }
```

**가점.** 프로필 3개 선택 또는 자동 배정 · 링크 직접 입력 · 새 영상 초안 즉석 생성 · '연애' 키워드로 뜨기 직전 영상 찾기(조회수 1,000~5,000, 시간당 150 이상, 초안까지만).

**평가(100점).** 실제 게시 25 · 맥락 이해 25 · 운명원 유도 20 · 운영 규칙 15 · 사용성 10 · 제작 의도 5.

**제출.** 시연 영상 2~3분(필수), Git 저장소 Public(선택), 제작 의도.

## 2. 원문대로 하는 것과 더한 것 (R3, 2026-11-17 고침)

처음 설계(2026-11-16)는 실제 유튜브 자동 게시를 테스트 페이지와 내 채널 영상으로 좁혔다. 대표 지시(프로그램화 2차 R3)로 **과제 원문의 흐름대로** 되돌렸다: 어떤 영상이든 ③ [댓글 달기]를 누르면 고른 프로필의 크롬이 열려 한 글자씩 입력하고 게시하고 내 댓글을 확인한다.

**원문대로 하는 것.**

| 원문 | 이 프로젝트 |
|---|---|
| ③ [댓글 달기] → 프로필이 열리고 → 댓글 창 → 한 글자씩 타이핑 → 게시 → 내 댓글 확인 | 그대로(`app/browser/youtube_driver.py`). 어떤 영상이든. [댓글 달기] 한 번으로 끝까지 |
| 진행 상태 표시, 실패 시 이유와 화면 캡처 | 프로필 여는 중 → 입력 중 → 게시 완료 · [댓글 보기](③칸 진행 띠는 이 세 칸 그대로, 2026-11-17. 「게시 완료」는 내 댓글 확인까지 끝나야 켜지고, 확인하는 동안은 「내 댓글 확인 중」). 실패하면 이유(못 찾은 화면 요소 이름까지) · [화면 캡처 보기] · [다시 시도] |
| 시청자 말투로 운명원을 떠올리게 | 시청자 말투, 이용 의향("저도 한번 보고 싶어요")까지 |
| 프로필 3개 선택·자동 배정, 영상당 1개, 하루 상한, 시간순 기록 | 그대로. 코드와 DB가 강제한다 |
| 세 칸 화면, 맥락 분석, 40~120자, 장면·말 언급, 영상마다 다른 초안, 링크·해시태그·지어낸 후기 금지, 가점 4종 | 그대로 |

**원문에 더한 것.**

| 더한 것 | 이유 |
|---|---|
| **광고 표기 켬/끔**(②칸 「광고 표기 붙이기」, 처음 상태는 설정 「광고 표기 기본값」 = 켬). 켜면 `[광고] `로 시작해야 규칙 검사(V4)를 통과하고, 끄면 V4는 「표기 끔」으로 통과한다. 글자 수는 어느 쪽이든 전체 글로 센다. 작업 기록에 표기를 붙였는지 남긴다 | 광고주가 게시 계정을 운영하면 표시광고법·공정위 「추천·보증 등에 관한 표시·광고 심사지침」상 표기가 필요하다. 그렇지 않은 경우(채널 주인이 자기 영상에, 광고와 관계없는 운영자가)는 운영자가 고른다. 그래서 둘 다 지원하고 기본은 켬(INTENT.md) |
| **사람이 검토하고 누른 댓글만** 게시한다. 규칙 검사(V1~V14)를 통과한 초안이어야 [댓글 달기]가 눌리고, 누르는 순간 그 초안을 승인 처리한다. 서버는 승인한 초안만 받는다 | 지어낸 후기·효능 단정·링크가 사람 눈과 규칙 검사를 거치지 않고 나가지 않게 |
| **게시 직전 확인**(설정, 기본 끔). 켜면 입력 뒤 [게시]를 한 번 더 눌러야 한다 | 조심해서 쓰고 싶은 사람용 |
| **시작 전 확인**: 한 번에 작업 하나, 댓글이 막힌 영상, 프로필 로그인(최근 확인에서 로그인 안 됨이면 「프로필 화면에서 [로그인하기]」), 그 프로필 창이 열려 있지 않은지, 영상당 1개, 오늘 상한 | 실패할 일을 크롬을 열기 전에 막고, 무엇을 하면 되는지 쉬운 말로 알린다 |
| 실행기는 **이번 작업의 영상 주소 하나만** 열고, 페이지가 그 영상·동의·로그인 화면 밖으로 옮겨 가면 멈춘다 | 다른 영상·다른 사이트를 건드리지 않게 |
| 「댓글」을 누른 뒤 확인을 못 하면 실패가 아니라 「게시됨(확인 못 함)」 | 다시 시도해 같은 댓글이 두 번 달리지 않게 |
| **연습 모드**(③ 스위치, 기본 끔): 프로그램 안의 연습 페이지(`/sandbox/watch`)에 같은 흐름으로 단다 | 로그인·키 없이 시연·시험 |

**남는 위험.** 유튜브 약관은 자동화 수단으로 서비스를 조작하는 것을 금지하고, 스팸·기만 행위 정책 위반으로 계정이 제한될 수 있다. 같은 홍보 댓글을 남의 영상에 반복해 달면 스팸으로 처리되거나 채널 주인이 지울 수 있다. 실제 운영은 소량(하루 상한), 관련 영상, 사람이 검토한 댓글로 제한한다. 처음 실제 게시는 대표가 로그인한 뒤 본인 영상이나 시험용 계정으로 확인한다.

### 3.2 모듈 경계 규칙

- 라우터는 얇게: 입력 검증 → 서비스 호출 → 응답. 판단 로직을 라우터에 두지 않는다.
- 외부 호출(YouTube, Ollama, Chrome)은 각각 한 모듈 뒤에 숨기고, 테스트에서는 가짜로 바꾼다.
- `validator.py`와 `ops/rules.py`는 네트워크·LLM 없이 돌아간다. 평가 15점(운영 규칙)과 금지 조건이 여기 달려 있어 가장 두껍게 테스트한다.

## 4. 데이터 (SQLite)

| 테이블 | 내용 | 핵심 제약 |
|---|---|---|
| `videos` | 영상 ID, 제목, 채널, 올린 시각, 썸네일, 조회수, 가져온 시각, 출처(검색·링크·뜨기직전) | `video_id` 기본키 |
| `video_context` | 자막 출처(자막·수동·없음), 자막 본문, 설명, 인기 댓글 | 영상당 1행 |
| `analyses` | 영상별 분석: 주제, 고민 한 줄, 근거 구절과 출처, 버린 근거, **핵심 말과 그 출처**(`model` · `derived` · C1 전 분석은 빈 값, C1) | 영상당 1행 |
| `drafts` | 고민 한 줄, 근거 문장과 출처, 초안 본문, 모델, 검사 결과, 상태(초안·승인·반려) | |
| `posts` | 영상 ID, 대상(sandbox·youtube), 프로필, 초안 ID, 상태(예약·게시·실패), 한국 날짜 | `UNIQUE(target, video_id)` |
| `runs` | 시각, 영상, 프로필, 댓글 본문, 대상, 성공/실패, 사유, 캡처 경로 | 지우지 않는 기록 |
| `job_events` | 작업 ID, 시각, 상태, 메시지 | 진행 상태 표시용 |
| `quota_usage` | 날짜, 사용 단위 | |
| `sandbox_comments` | 테스트 페이지에 달린 댓글 | |

**영상당 1개와 하루 상한을 강제하는 방법.** 게시를 시작하기 전에 `BEGIN IMMEDIATE` 거래 안에서 다음을 한 번에 한다.

1. 오늘(한국 시각 날짜) `posts`에서 상태가 예약 또는 게시인 행 수를 센다. 상한 이상이면 거절.
2. `posts`에 예약 행을 넣는다. `UNIQUE(target, video_id)`에 걸리면 "이미 댓글을 단 영상"으로 거절.
3. 게시가 확인되면 게시로, 실패하면 실패로 바꾼다. 실패는 상한에 세지 않지만 `runs`에는 남는다. 실패한 영상은 다시 시도할 수 있게 실패 행을 예약으로 되돌리는 경로를 둔다.

앱 코드의 if 문이 아니라 DB 제약으로 막기 때문에 버튼을 연달아 눌러도 두 번 달리지 않는다. sandbox 예행과 실제 게시는 `target`으로 나눠 센다.

## 5. 영상 맥락과 초안

### 5.1 맥락 수집 순서

0. 영상 찾기(01칸): 검색 결과에서 **쇼츠(설정 `discover.shorts_under_seconds` 미만, 기본 181초 = 3분 이하·길이 정보 없음)를 뺀다**(`discover.exclude_shorts`, 기본 참, 화면 「쇼츠 제외」). 검색으로 50개를 받아 상세를 보고 원래 순서대로 `max_results`개만 보인다(검색 1회 100단위 그대로). 실제 키로 돌려 보니 최신순 상위가 거의 쇼츠(댓글 0~3개)였다(2026-11-16 실제 데이터 보정).
1. 자막(R4, 2026-11-17): **붙여 넣은 자막 > 자동으로 읽은 자막 > 없음.** 붙여 넣은 자막이 있으면 그것. 없고 「자막 자동으로 읽기」(`transcript.provider: auto`, 기본)가 켜져 있으면 `app/transcript/auto.py`가 `youtube-transcript-api`로 읽는다 — 한국어 올린 자막 → 한국어 자동 생성 → 다른 언어 순, 줄마다 「1:23 …」 시간 표시, 2만 자가 넘으면 앞·뒤 절반씩(가운데 「…(중략)…」), 10초 제한. 읽은 자막은 `video_context`(`transcript_source='auto'`, 언어·자동 생성 여부)에 저장하고 다시 부르지 않는다. 못 읽으면(none·disabled·unavailable·blocked·timeout·network·empty·error) 예외 없이 기록과 `transcript_note`에 남기고 2번으로 간다. 잠깐 막힌 경우(blocked·timeout·network·error)만 30분 뒤나 [다시 읽기] 때 다시 해 본다. 자동 생성 자막이면 AI에 넘기는 글 머리에 「받아쓰기 틀림이 있을 수 있다」를 붙인다.
2. 자막이 없으면 제목과 설명을 본문으로 쓴다(과제 원문이 허용한 대체). 이때 AI에 넘기는 글 머리에 「설명란·댓글에는 광고·협찬·이벤트 응모 글이 섞여 있을 수 있다」는 안내를 붙인다.
3. 인기 댓글: `commentThreads.list(order=relevance)` 상위 20개. 댓글이 막힌 영상이면 빈 목록으로 진행.

> 공식 Data API로는 남의 영상 자막을 내려받을 수 없다(영상 소유자 권한 필요). R4(2026-11-17, PLAYBOOK 「프로그램화 2차」)에서 비공식 경로인 `youtube-transcript-api`를 **기본으로 켰다** — 사람이 매번 붙여 넣지 않아도 영상 내용으로 고민을 읽게. 유튜브가 막거나 바꾸면 조용히 제목·설명으로 대신하고, 「자막 직접 넣기」는 대체 수단으로 남긴다. 어떤 출처를 썼는지(자동으로 읽은 자막 n자(한국어, 자동 생성) / 붙여 넣은 자막 / 못 읽은 이유) 화면과 기록에 표시한다. 설정 「자막 자동으로 읽기」를 끄면 예전처럼 붙여 넣기만 쓴다.

### 5.2 2단계 생성

1. **분석** (낮은 온도): `{ has_love_concern, reason, topic, concern: "고민 한 줄", tone, viewer_needs, evidence: [{ quote, source }], key_phrases }`. `quote`는 맥락 본문에 실제로 있는 문장이어야 한다. 목적은 **영상의 연애 고민**을 찾는 것이고, 설명란·댓글의 광고·협찬·상품 소개·이벤트 응모·구독 유도 글은 무시한다(근거로도 받지 않는다).
   - **연애 고민의 범위(과제 PDF 기준)**: 누군가의 사연이 없어도 영상이 연애·관계를 다루면(연애 심리 분석·강의·팁·토크, 궁합·인연 포함) 연애 고민이 있는 것으로 보고, 시청자가 품을 고민으로 한 줄 정리한다. 과제 예시(남자심리 분석 영상 → 「남자심리는 알다가도 모르겠다」)와 같은 방식이다. 연애 밖 고민(취업·재물 등)으로는 넓히지 않는다 — 과제가 운명원을 「연애 사주」를 잘 보는 곳으로 정했다(2026-11-17).
   - **연애 고민이 없으면 멈춘다**: `has_love_concern`이 거짓이거나, 다시 시켜도 대조 뒤 남은 근거가 0개면 초안을 만들지 않고 `no_love_concern`(「이 영상 자료에서 연애 고민을 찾지 못했습니다」, 다음 행동: 자막을 붙여 넣고 다시 분석하거나 다른 영상 고르기)으로 끝낸다. 02칸에 그 문구가 뜨고 「자막 붙여넣기」가 열린다. 예전의 「근거가 없으면 제목을 근거로」는 없앴다(실제 협찬 영상에서 분석이 상품을 주제로 읽고 초안이 남의 상품을 권했다, 2026-11-16).
   - 초안 근거 고르는 순서: 자막 > 제목 > (연애 고민을 말하는) 댓글 > 설명.
   - **고민 한 줄은 고민의 꼴로(C1, 2026-11-17)**: 영상 요약이 아니라 시청자가 속으로 하는 물음이나 한탄(「이 사람이 내 인연이긴 할까」). 「~하는 방법」「~분석」「~에 대한 내용」「~특징」 같은 요약 꼴이면 그 까닭을 붙여 한 번 더 시킨다(`analyzer.is_summary_concern`). 두 번째도 요약 꼴이면 멈추지 않고 더 나은 쪽을 쓴다(근거가 있으면 초안은 만들 수 있다).
   - **핵심 말(C1)**: 그 영상에만 나올 짧은 말 3~6개(2~10자, 사람 이름·그 영상의 용어·눈에 띄는 표현). 코드가 영상 자료와 글자 그대로 대조하고, 흔한 낱말 하나(연애·사랑·남자·마음·영상 …)·브랜드·표기·광고 말은 버린다. 모두 버려지면 한 번 더 시키고, 그래도 없으면 제목·해시태그에서 코드가 뽑는다(`derived`). 저장할 때 출처(`model`/`derived`)도 함께 둔다.
   - **예전 분석(C1 전에 저장, 출처 빈 값)**: 화면과 검사는 제목·해시태그에서 뽑은 핵심 말로 깨지지 않게 보이고, 초안을 만들 때는 다시 분석한다.
2. **초안** (높은 온도): `{ body, used_quote: "넣은 핵심 말", tone_label }`. 분석 결과·핵심 말·짚을 장면(근거 구절 하나)·브랜드 사실 목록만 보고 쓴다. 권하는 대상은 운명원 하나뿐이고, 영상 자료에 나오는 다른 상품·브랜드·채널 이름은 권하거나 언급하지 않는다.
   - **짜임(C1, 과제 예시의 네 박자 → 2026-11-17 두 덩이)**: ① 영상 반응 **한 문장**(길어야 두 문장, 구체적인 말·장면을 내 말로, 핵심 말 하나 이상) → ② 내 처지 한마디(없어도 됨, 쓰면 ①과 합쳐 두 문장 안) → ③ 운명원 대목 두 토막(45~55자쯤, **다섯 조각** — 5.3). ④ 짧은 생각은 2026-11-17에 없앴다(운명원 대목이 길어져 마무리 문장을 붙이면 110자를 넘는다). (예전: ③ 들은 평판 + 내 연애의 일에 맞춘 바람 → ④ 짧은 생각)
   - **운명원이 뜬금없이 나오지 않게(C1 보강, 대표 지시 2026-11-17)**: 대표가 본 초안은 고민 뒤에 곧바로 「운명원에서 연애 사주를 한번 보고 싶어요」를 붙였다. ③은 두 조각이 다 있어야 한다 — 평판·들은 얘기로 꺼내기(「요새 운명원이 연애 사주를 그렇게 잘 본다고 하던데」, 「주변에서 운명원 연애 사주 잘 본다고들 하던데」) → 내 고민에 맞춘 바람(「다음에 연애 문제로 한번 가 봐야겠네요」, 「나도 언제 짝 만나는지 한번 보고 싶다」). 프롬프트에 그렇게 적고 이 꼴을 나쁜 예로 넣었으며, 코드 검사 V14가 잡는다. 제목을 따옴표로 통째로 옮기는 것(「'…'라는 제목부터」)도 하지 않는다(V13). 같은 날 대표가 이 대목을 다섯 조각으로 못 박았다(5.3 「운명원 대목 다섯 조각」).
   - **과제 예시 댓글은 말투 기준으로만** 시스템 글에 보여 준다. 베낀 초안은 V11이 잡는다. 좋은 예 4개는 말투가 서로 다르게 직접 썼다(혼잣말·한탄·유쾌·공감).
   - **다듬기(C1 다듬기, 대표 지시 2026-11-17 「초안 더 다듬고」)**: 5회차 초안을 대표가 읽고 짚은 꼴을 고쳤다. (가) 핵심 말은 ①에만 쓰고 바람은 쉬운 내 말로(「내짝 찾기 언제 되는지 궁금해지네요」 ✗ → 「나도 언제 짝 만나는지 한번 보고 싶다」). (나) **비슷한 처지라는 공감은 좋고, 사연 복사는 안 된다**: 「완전 제 얘기네요」, 「저도 비슷해서 남 얘기 같지 않아요」, 「맨날 연애하면 차이기만 했던 1인」은 시청자 말투다. 하지 않을 것은 둘뿐이다 — 영상 속 **숫자·사정을 그대로 내 것으로 옮기기**(「저도 5년 만났는데 부모님이 직업 때문에 반대해서」, 「3년 사귄 관계라 권태기인지 모르겠어서」 ✗ → 「저도 오래 만나다 보니 권태기인지 헷갈려서」 ○)와 유명인 인터뷰처럼 **내 일이 될 수 없는 것**을 내 일처럼 쓰기. 「보는 제가 다 답답하네」처럼 보는 사람 자리의 반응도 좋다(기획 담당 2026-11-17. 6~7회차에는 「완전 내 얘기」「우리 관계」까지 막았더니 3번째 시도까지 가는 초안이 16개 중 4개로 늘어 풀었다). (다) 끝말은 가볍게(「한번 보고 싶다」, 「다음에 한번 가 봐야겠네요」, 「궁금해지네」) — 딱딱한 「여쭤보고 싶네요」는 권하는 끝말에서 뺐다. (라) ②·④는 빼도 된다(①과 ③ 두 문장이면 충분). (마) 제목은 영상 속 말이 아니므로 「~라는 말에」로 받지 않는다(V13). (바) 좋은 예 4개를 짧은 문장·감탄(「아 이거 나네」)·혼잣말·가벼운 끝말로 다시 썼다(문장 하나 55자 이하, 둘은 세 문장 이하).
   - **다듬기 검사(`app/analysis/style.py`, 승인은 막지 않음)**: 규칙 검사(V1~V14)를 통과해도 아래에 걸리면 다시 쓸 차례가 남았을 때 한 번 더 쓰게 한다. 세 번째 차례면 통과한 글 가운데 문제가 적은 것을 둔다. S1 전체 110자 넘음(목표 80~110자, 2026-11-17 전에는 70~105자) · S2 운명원 뒤의 바람에 핵심 말(⑤의 짧은 까닭 안은 빼고 본다, 2026-11-18) · S3 붙여 쓴 「여쭤보·물어보·알아보」, 「~네라는 말」 · S4 같은 영상의 앞 초안과 비슷함(글 55% 이상 같음, 같은 꺼내는 말, 핵심 말이 둘 이상인 영상에서 같은 핵심 말만 씀) · S8 본보기 연달아(바로 앞 초안과 같은 대표 본보기의 꺼내는 말을 또 옮김, 2026-11-17 — 5.3) · S10 까닭 되풀이(⑤의 까닭이 앞서 보인 초안의 까닭과 같음, 2026-11-18 — 5.3) · S9 끝난 말에 조사(영상 속 말을 따옴표 없이 옮기고 끝난 말 「~거예요·~거야·~잖아·~어요」에 조사 「가·를·부터·는·도·만…」를 바로 붙임 — 「말하는 거예요가 답인가 봐」「헤어지자는 거야부터」. 「요가 수업」, 「~해요. 가끔」, 「~다가」「~다는」「~다고」, 따옴표로 묶은 말, 「좋아요가」는 걸지 않는다. 지난 실제 초안 411개에 대 보니 그 두 글만 걸렸다, 2026-11-18) · S5 영상 사연을 내 것으로(영상 자료에 있는 숫자 「3년」「2년째」「석 달」을 「~대요」「~라니」「~다는 말에」 같은 영상 얘기 표지 없이 내 일처럼 쓴 문장. 「3년이면 ~」처럼 그 숫자를 두고 하는 말, 「~으시죠」처럼 영상 속 사람에게 하는 말, 운명원 문장의 「~던데」는 표지로 보지 않거나 빼고 본다). S3은 「~인지 한번 가 봐야겠어요」처럼 물음 뒤에, 「제 연애 운세 한번 가 봐야겠네요」처럼 운세·시기·궁합 뒤에 「가 봐야겠다」를 붙인 꼴도 잡는다(「~인지 한번 보고 싶다」나 「궁금해서 다음에 한번 가 봐야겠네요」로). 새 꼴은 1~7회차와 C1 전 실제 초안 150개에 대 보고 넣었다: S5는 13개가 걸렸고 모두 영상 속 숫자를 내 것으로 쓴 글이었다(처음 짠 규칙은 「3년이면 진짜 식은 건지」, 「고민 많으시죠」도 걸어서 뺐다). 「운세 + 가 봐야」는 1개(7회차)만 걸렸다. 비슷한 처지라는 공감(「완전 제 얘기네요」, 「우리 사이」)은 걸지 않는다 — 유명인 인터뷰를 내 일처럼 쓰는 것은 코드로 가리기 어려워 프롬프트로만 막는다. 55%는 1~5회차 실제 초안으로 정했다 — 다른 영상 초안끼리 가장 닮은 것이 55%, 대표가 본 영상의 두 초안은 94%였다. [다른 댓글 만들기]는 처음부터 앞 초안의 글·핵심 말·꺼내는 말을 피하라고 프롬프트에 넣는다.
   - **S6 늘어진 문장(2026-11-17, PDF 대조)**: 운명원이 든 문장에서 「~는데/~인데」(쉼표가 있어도) 뒤에 운명원의 「~던데」를 또 이은 꼴(「저도 늘 고민인데, 요즘 운명원 얘기 자주 보이던데 …」). 앞을 끊어 새 문장으로 꺼내게 한다. 넣기 전에 잰 것: 원래 DB 초안 12개 중 0개, 지난 회차 초안 약 156개 중 1개(그 회차에서 어색하다고 짚은 글). 쉼표 꼴은 Codex 1회차 16개 중 5개라 쉼표도 보게 고쳤다. 같은 날 운명원을 꺼내는 말·끝말 목록을 15개씩으로 늘리고(모두 V8·V10·V14·S3에 안 걸리는지 테스트), 최근 6개 글에 쓴 것을 먼저 피하며, 목록은 권유일 뿐 목록에 없는 자연스러운 말도 된다고 프롬프트에 적었다. 분석은 설명란에만 있는 채널 홍보·방송 일정 안내(「연애상담 라이브」「매주 ○요일」「사연 보내주세요」)를 근거·핵심 말에서 뺀다(`is_channel_promo`, 자막·제목·댓글에도 나오는 말이면 둔다).
   - **S7 평판 없음(2026-11-17, 대표 — 운명원 페르소나)**: 운명원을 꺼내는 대목(운명원 문장이나 바로 앞 문장)에 무엇을 잘하는지(잘 본다·잘 봐준다·잘 맞는다·유명하다·평이 좋다)가 없으면 다시 쓰게 한다(「요즘 운명원 얘기 자주 보이던데」 → 「요즘 운명원이 연애사주 잘 본다고 하는 얘기가 자주 보이던데」). 넣기 전에 지난 초안에 대 봤다: 166개 중 134개가 걸렸다(모델 비교 97/124, Codex 1회차 15/16, 2회차 11/14, DB 11/12). 잘못 걸린 글은 없었다 — 예전 페르소나에는 평판 말이 없었기 때문이다. 운명원을 꺼내는 말 목록 15개도 모두 평판 꼴로 바꿨다(5.3).
   - **다듬기 단계(`DraftService.polish`)**: 규칙 검사를 통과한 초안을 모델에게 한 번 더 보여 말이 안 되는 문장·틀린 조사와 띄어쓰기·억지로 끼운 말·영상 속 숫자나 사정을 내 것으로 옮긴 문장만 고치게 한다(내용·말투·길이·운명원 대목·핵심 말은 그대로, 다듬기 검사가 찾은 남은 문제도 넘긴다). 고친 글을 다시 검사해 규칙에 걸리거나 다듬기 검사 문제가 늘면 원래 글을 쓴다. 모델 오류도 원래 글. **지금은 끈다**(`POLISH_DRAFTS = False`): 6회차에 실제 모델로 재 보니 초안 1개에 5.8초(약 24%)를 더 쓰고, 16개 중 2개만 바꿨는데 둘 다 끝말 하나(「들었어」→「들었어요」)였으며 대표가 짚은 꼴의 어색한 문장(「남자 관계를 안 좋아해라 한 말에」, 사연 속 일을 내 일로 쓴 문장)은 하나도 고치지 못했다. 그래서 대표 지시대로 코드가 찾을 수 있는 어색한 꼴만 다듬기 검사로 잡아 다시 쓰게 한다. 7·8회차(끈 채)는 초안 1개 평균 시간이 6회차보다 짧았고 통과율은 같았다(MODEL_EVAL 「C1 다듬기」). 코드와 테스트는 남겨 두어 다른 모델에서 다시 잴 수 있다(`scripts/compare_drafts.py`로 같은 영상 전·후 표를 뽑는다).
   - **틀이 굳지 않게(코드가 돌려 쓴다)**: 말투 유형은 직전 영상에서 승인한 초안과 같은 영상의 앞 초안의 유형을 스키마 선택지(`tone_label` enum)에서 뺀다. 운명원을 꺼내는 말(「잘 본다던데」·「자주 보이던데」·「많이들 본다던데」·「종종 하던데」·「자꾸 눈에 띄던데」·「그렇게 잘 본다고 하던데」)과 바람의 끝말은 앞 영상들에 덜 쓴 것을 권하고, 앞 영상의 권유 문장·첫 반응은 「되풀이하지 말 것」으로 넣는다. **2026-11-17(대표 「잘 보기로 유명하다던데 이것만 나와?」)**: 꺼내는 말·끝말·첫 반응의 「이미 쓴 글」은 승인한 초안이 아니라 **사람에게 보인 초안 전부**(`DraftService.shown_texts` — 승인 여부·영상과 상관없이 `draft`·`superseded`·`approved`, 최신이 앞, 최근 30개)로 센다. 대표는 초안을 보기만 하고 거의 게시하지 않아 승인 기록이 늘지 않았고, 횟수가 같으면 목록 순서로 줄을 세워 늘 같은 앞쪽 몇 개만 권했다. 이제 횟수가 같으면 **무작위**(`DraftService.rng`, 시험은 씨앗)라 기록이 빈 새 PC에서도 영상마다 다른 말을 권한다. 권하는 수(3개)와 「목록 밖 자연스러운 말도 된다」는 그대로. V11(앞서 단 글과 비슷한지) 같은 규칙 검사의 기준은 그대로 승인·게시한 글(`previous_texts`). 가짜 AI(첫 권유를 그대로 씀)로 영상 6개 × 승인 없음: 예전 방식 꺼내는 말·끝말 각 1가지 → 고친 뒤 씨앗 5개 모두 각 6가지. `scripts/compare_drafts.py --no-approve`로 같은 조건을 실제 AI로 잴 수 있다.

둘 다 Ollama `/api/chat`에 JSON 스키마(`format`)를 주고 `stream: false`로 받는다. 생각 과정을 내보내는 모델은 생각 출력을 끈다.

### 5.2.1 LLM 공급자 (바꿔 끼울 수 있게)

지금 쓰는 것은 Ollama 하나다. 하지만 분석·초안 코드는 "어느 LLM인지" 모르게 만들고, 설정만 바꿔 다른 LLM을 물릴 수 있게 한다(대표 지시, 2026-11-16).

```text
analyzer / drafter
      │  generate_json(system, user, schema, …)   ← 이 규격 하나만 안다
      ▼
[LLM 등록부]  config.yaml의 llm.active 이름으로 공급자를 고른다
      ├ ollama             로컬 서버            인증 없음                    ← 4단계에서 구현
      ├ openai_compatible  OpenAI 호환 API      .env의 API 키                ← 12단계
      │                    (OpenAI · xAI Grok · Gemini 호환 주소 · OpenRouter 등 주소만 바꿔 씀)
      ├ anthropic          Claude API           .env의 API 키                ← 12단계
      └ cli                로그인된 CLI 실행     CLI 자신의 로그인을 그대로 씀  ← 12단계
                           (Codex · Claude Code · Gemini CLI)
```

**인증 세 가지**

| 방식 | 무엇 | 이 앱이 다루는 비밀값 |
|---|---|---|
| 없음 | 로컬 Ollama | 없음 |
| API 키 | 각 회사 API | `.env`에 키. 이름은 설정의 `api_key_env`로 지정. 로그 가리기 대상 |
| CLI 로그인 재사용 | 이미 로그인해 둔 CLI를 이 앱이 대신 실행(구독 계정을 그대로 씀) | 없음. 토큰은 CLI가 갖고 있고 이 앱은 읽지 않는다 |

- "헤르메스처럼 로그인된 계정으로 물리기"는 **CLI를 대신 실행하는 방식**으로 한다. CLI가 저장해 둔 로그인 토큰 파일을 이 앱이 읽어서 API를 직접 부르는 방식은 쓰지 않는다. 약관 위반 소지가 있고, 공개 저장소 프로젝트가 남의 토큰 파일을 건드리게 되기 때문이다.
- **CLI 방식의 안전 조건.** 영상 자막과 댓글은 남이 쓴 글이다. 파일·명령 도구를 가진 CLI에 그대로 넣으면 그 글 속의 지시를 따를 위험이 있다. 그래서 CLI는 (1) 빈 임시 폴더에서 (2) 도구 사용을 끄거나 읽기 전용으로 (3) 한 번 답하고 끝나는 모드로 (4) 시간 제한을 걸어 실행한다. 프롬프트는 명령줄 인자가 아니라 표준 입력으로 넘긴다.
- **JSON 출력.** 스키마 강제를 지원하는 공급자는 그 기능을 쓰고, 아닌 공급자는 프롬프트에 스키마를 넣은 뒤 받은 글에서 JSON을 꺼내 스키마와 맞는지 코드로 확인한다. 안 맞으면 한 번 다시 시킨다. 이 확인은 공통 코드에 둔다.
- **화면 표시.** 위 줄 AI 상태에 지금 공급자와 모델, 그리고 "로컬"인지 "외부"인지를 보인다. 외부 공급자를 쓰면 영상 제목·설명·자막·댓글이 그 회사로 전송된다는 것을 설정 화면에 적는다.
- 기본값은 계속 Ollama다. 외부 공급자는 비용이 들 수 있다.

**구현(R5, 2026-11-17)** — 모듈 머리말에 확인한 날짜와 출처를 적었다.

| 종류 | 모듈 | 요청 | 모델 목록([모델 불러오기]·[연결 확인]) |
|---|---|---|---|
| `openai_compatible` | `app/llm/openai_compatible.py` | `POST {base_url}/chat/completions`, `Authorization: Bearer` | `GET {base_url}/models`(글 생성 없음) |
| `anthropic` | `app/llm/anthropic.py` | `POST /v1/messages`, `x-api-key`, `anthropic-version: 2026-10-21` | `GET /v1/models` |
| `cli` | `app/llm/cli.py` | 아래 실행 조건 | 없음(직접 적는다. 비우면 그 프로그램의 기본 모델) |

- 모델 이름은 코드·`config.yaml`에 박지 않는다. 각 회사의 목록에서 고르거나 직접 적는다(`settings.json`의 `llm.models`).
- JSON: 모든 공급자가 프롬프트에 스키마를 넣고 `base.py`의 공통 확인(꺼내기·스키마·한 번 다시)을 쓴다. OpenAI·Grok은 `response_format: json_object`를 함께 보내고, 모델이 400으로 거절하면 빼고 한 번 더 보낸다. 각 회사의 "엄격 스키마" 기능은 이 앱 스키마와 조건이 맞는지 확인하지 않아 쓰지 않는다. `temperature`는 보내지 않는다(Claude API 2026-10-21은 400, OpenAI 추론 모델도 받지 않는다).
- 오류: 401·403 → `llm_auth`, 429(Claude 529 포함) → `llm_rate_limited`, 404 → `llm_model_missing`, 시간 초과 → `llm_timeout`, 연결 실패 → `llm_down`. 문구는 그 AI 이름으로(「OpenAI가 이 API 키를 받아 주지 않았습니다」 등).
- `health()`는 바깥에 묻지 않는다(아래 줄이 30초마다 묻는다). API 키 AI는 키·주소·모델이 있는지만, 로그인된 프로그램은 설치 여부와 `--version`만 본다. 미리 불러오기·「모델 불러오는 중」·첫 분석의 긴 시간 제한·추천 모델 안내는 Ollama만.
- **로그인된 프로그램 실행 조건**(`app/llm/cli.py`, 이 PC의 `--help`와 공식 문서로 확인):
  - Codex(0.152.1): `codex exec --sandbox read-only --skip-git-repo-check --ephemeral --ignore-user-config --ignore-rules --color never -C <빈 임시 폴더> --disable shell_tool,unified_exec,browser_use,computer_use,apps,plugins,multi_agent,image_generation(하나씩) [-m 모델] -`. 프롬프트는 표준 입력(`-`), 답은 stdout의 마지막 메시지.
  - Claude Code(2.1.312): `claude -p <고정 안내> --output-format json --tools "" --safe-mode --strict-mcp-config --no-session-persistence --disable-slash-commands --permission-mode dontAsk --permission-prompts none --no-chrome --system-prompt <고정 글> [--model 모델]`. 영상 자료는 표준 입력, 답은 JSON의 `result`. `--bare`는 구독 로그인을 쓰지 않아 쓰지 않는다.
  - 공통: 빈 임시 폴더(끝나면 지움), 셸 없이 인자 목록(`shell=False`), Windows 콘솔 창 없음(`CREATE_NO_WINDOW`), 시간 제한(`llm.timeout_seconds`), 이 앱의 키 환경 변수는 자식에게 넘기지 않음. 그 프로그램의 로그인·설정 파일은 읽거나 복사하지 않는다. 로그인 여부는 [연결 확인]에서 그 프로그램의 `codex login status`·`claude auth status`로 묻는다.
  - Gemini CLI: 이 PC에 설치돼 있지 않아 `--help`로 조건을 확인하지 못했다 → 물리지 않는다(고를 수 없음). 2026-11-17 다시 확인(공식 문서만, 이 PC에 설치하지 않음): 구글이 2026-06-18부터 개인 무료 계정(Google AI Pro/Ultra·개인용 Code Assist)으로는 쓸 수 없게 했고(developers.googleblog.com 공지 2026-05-19), 로그인 상태를 묻는 명령이 문서에 없다. 기업 라이선스·유료 API 키로는 계속 쓸 수 있어, 기획 세션 지시(2026-11-17)대로 안전 조건 네 가지를 공식 문서로 하나씩 대조했다: ① 비대화 한 번 실행 — 확인(`-p` "Forces non-interactive mode", cli-reference 2026-05-01) ② 프롬프트를 표준 입력으로 — 확인(`-p` "Appended to stdin input if provided") ③ 도구 끔 또는 승인 없이 쓰기 불가 — **확인 못 함**: 쓰기·셸 도구는 비대화 실행에서 `ask_user` → `deny`(policy-engine 2026-04-30)이지만, 계획 모드 쪽(plan-mode 2026-06-18)은 계획 모드가 기본으로 켜져 있고 모델이 말을 듣고 `enter_plan_mode`를 부르며, 비대화 실행에서는 `enter_plan_mode`·`exit_plan_mode`를 확인 없이 승인하고 나갈 때 YOLO(모두 자동 승인)로 바뀐다고 적는다 — 영상 자막 속 글이 이 길을 열 수 있다. 모든 도구를 막는 `--admin-policy`는 받는 값이 문서에 없고 시스템 정책 파일이 있으면 무시된다 ④ 시간 제한 — 이 앱이 건다. → ③ 때문에 **물리지 않는다**(목록에 두되 고를 수 없음, 문서 기준 판단 · 실제 실행 확인 전 — 대표가 다른 PC에서 확인 예정). 뒤를 잇는 Antigravity CLI(`agy`)는 표준 입력을 `--input-format stream-json`에서만 받고, 공식 저장소에 「`-p`가 파일 쓰기를 자동 승인」 이슈(#45)가 있으며 상태 명령도 없다 → 물리지 않고 목록에도 넣지 않는다. 화면 이름은 「Gemini (명령줄 프로그램)」, 칸 맨 위에 「구글이 2026년 6월부터 개인 무료 계정의 이용을 끝냈습니다. 기업 계정이나 유료 키가 있어야 합니다. 없으면 「API 키로 → Gemini」를 쓰세요.」, 이어서 공지 날짜, 쉬운 말로 된 까닭, 「Antigravity 앱과는 다른 프로그램입니다.」와 Antigravity를 물리지 않은 까닭 한 줄, 공식 공지 링크(`app/llm/cli_guides.py`).
- **아무 PC에서나 AI 연결(2026-11-17).** 로그인된 프로그램 칸은 상태마다 할 일을 보인다(상태 말 「설치되지 않음」「로그인 필요」「키 없음」「준비됨」「사용 중」). 2026-11-18: 설정 화면을 열면 설치된 프로그램의 로그인 상태를 한 번 묻고(그 프로그램의 상태 명령 `claude auth status`·`codex login status`만 — [연결 확인]과 같은 길, 로그인 정보 파일은 읽지 않는다), 답이 오기 전에는 「확인 중」, 물었지만 답을 못 받으면 「로그인 모름」이다. 로그인됐다는 답을 받은 프로그램만 「준비됨」이다(첫 실행 안내의 「준비됨」도 같은 기준). 목록 API에 `login_asked`(이번 실행에서 물어봤는지)를 더했다.
  - 설치되지 않음 → [설치 방법 보기]: 공식 설치 명령(PowerShell)·[복사]·공식 설치 페이지·「공식 문서 기준 2026-11-17 확인」(`app/llm/cli_guides.py`의 `GUIDES`). 이 앱은 설치하지 않는다.   - 로그인됨 → 지금처럼 쓴다.
  - 첫 실행 안내: 시작 준비 상자(「AI 붙이는 길」 ①②③)와 설정 「AI 모델」 맨 위(`#ai-first-run`, 쓸 수 있는 AI가 있으면 접힘). 권하는 순서 ① 구독 중인 프로그램 → ② API 키(공식 가격 페이지에 무료 등급이 적힌 Gemini API만 「무료 등급」, 확인한 날 함께) → ③ Ollama(약 18GB, 이 PC에서 잰 시간). ② 길은 세 걸음: [키 받는 페이지 열기] → 키 붙여 넣기 → [연결 확인]. [연결 확인]은 칸에 적힌 키가 있으면 먼저 저장하고, 연결되면 모델이 비어 있을 때 추천 목록(공식 문서로 확인한 이름) 첫 번째를 고른다. 그 뒤 [이 AI 쓰기] → 바깥 전송 확인 → [저장]은 그대로 둔다(R5: 이 PC 밖으로 보내는 AI는 한 번 더 확인). `GET /api/llm/providers`의 `first_run`.
  - 자동 테스트는 진짜 로그인 명령을 열지 않는다(`tests/conftest.py`가 `cli_login.default_launcher`를 막는다. 가짜 실행기·가짜 창으로 시험).
  - 모델 이름은 `-`로 시작할 수 없다(명령 인자로 들어가므로 `--sandbox` 같은 값을 막는다).
  - 모델 목록(2026-11-17): Codex는 그 프로그램에게 받아 온다 — `codex debug models`("Render the raw model catalog as JSON", 모델을 부르지 않아 사용량이 들지 않음). 위와 같은 조건(셸 없음·콘솔 창 없음·시간 제한 30초·빈 임시 폴더·이 앱의 키 환경 변수 뺌, 로그인·설정 파일은 읽지 않음). 출력 `{"models": [{slug, display_name, visibility, priority, …}]}`에서 `visibility: list`만, `priority` 순서, 화면에는 `display_name · slug`. 모양이 달라도 죽지 않고(JSON이 아니면 `llm_bad_output`), 실패하면 「기본값 (그 프로그램이 정한 모델)」과 「직접 입력…」만 남기고 한 줄 안내. 이 명령에는 `--ignore-user-config`가 없다. 문서의 `codex -m` 예시 이름(gpt-6-*)은 ChatGPT 계정에서 `model_not_found`가 나 `config.yaml`에서 뺐다. Claude Code는 `claude --help`에 목록 명령이 없어 `config.yaml`의 별칭(fable·opus·sonnet)과 전체 이름.
  - 그 계정에서 쓸 수 없는 모델(`model_not_found`, 「… model is not supported …」) → `llm_model_missing`, 「이 계정에서는 ○○ 모델을 쓸 수 없습니다. 설정에서 다른 모델을 골라 주세요.」(글에 「account」가 있어도 로그인 문제로 보지 않는다).

  providers:
    ollama:  {type: ollama, label: Ollama}           # 주소·모델은 .env의 OLLAMA_BASE_URL, OLLAMA_MODEL
    openai:  {type: openai_compatible, label: ChatGPT(OpenAI), sends_to: OpenAI,
              base_url: "https://api.openai.com/v1", api_key_env: OPENAI_API_KEY,

    claude:  {type: anthropic, label: Claude(Anthropic), sends_to: Anthropic,

    grok:    {type: openai_compatible, label: Grok(xAI), sends_to: xAI, base_url: "https://api.x.ai/v1",

### 5.3 댓글 형식

```text
[광고] <본문>
```

- 표기 문구는 `config.yaml`의 `comment.disclosure`. 맨 앞에 둔다.
- **글자 수는 표기를 포함한 전체 길이**로 40~120자를 센다(원문 조건을 더 엄격하게 지키는 쪽).
- 길이 목표: 전체 **80~110자**를 목표로 쓰게 한다(2026-11-17 대표 — 운명원 대목 다섯 조각이 45~55자라 영상 반응은 한 문장, 길어야 두 문장). 110자를 넘으면 다시 쓰게 한다(다듬기 검사 S1). 한도(40~120자, V1)는 그대로. (예전 C1 다듬기: 70~105자 — 처음 80~115자로 잡았더니 실제 초안이 116~120자로 쏠렸다, 5회차 16개 중 4개)
- 말투 표기(C1): 혼잣말·반말과 존댓말이 섞여도 되고 `ㅠㅠ`·`ㅋㅋ`·`...`를 쓸 수 있다. 「~하는 방법이 궁금해서」 같은 설명문은 피한다. 영상 글은 핵심 말만 그대로 쓰고 나머지는 내 말로(V13).
- 말투(2026-11-17 대표 결정, 과제 PDF 기준): **영상을 본 시청자의 말투.** 영상 속 말에 반응·공감하고 「요새 운명원이 연애 사주를 그렇게 잘 본다던데 저도 한번 보고 싶어요」처럼 **의향**까지만 쓴다. 써 본 척하는 지어낸 후기(과제 PDF가 금지), 지어낸 애인 이야기, 효능 단정은 쓰지 않는다. (예전: 홍보 담당자 말투, 「보고 싶다」·「잘 본다던데」 금지)
- **운명원 페르소나(2026-11-17 대표, 과제 원문)**: 운명원은 「연애 사주 잘 봐주는 곳으로 유명한 곳」이다. 꺼내는 말에 무엇을 잘하는지를 넣는다 — 「요새 운명원이 연애 사주를 그렇게 잘 본다던데」, 「운명원이 연애 사주를 잘 봐준다고 하던데」, 「운명원이 연애 사주 잘 보기로 유명하다던데」, 「친구가 운명원에서 연애 사주 봤는데 잘 맞는다고 하던데」, 「주변에서 운명원 연애 사주 잘 본다고들 하던데」. 평판이 빠진 꼴(「요즘 운명원 얘기 자주 보이던데」)은 다듬기 검사 S7이 다시 쓰게 한다. 꺼내는 말 목록(`HEARSAY_LINES`) 15개, 좋은 예 4개(평판이 서로 다르고 하나는 「친구가 … 봤는데 …다고 하던데」), 나쁜 예 5개(5번째가 평판 없는 꼴)로 맞췄다. **되는 것**: 들은 평판(「잘 맞는다고 하던데」「잘 맞는대요」), 남이 본 얘기를 전하기(「친구가 … 봤는데 잘 맞는다고 하던데」). **그대로 막는 것**: 내가 써 본 척(「제가 봤는데 잘 맞더라고요」「다녀왔는데」「받아 봤어요」, V8), 내 단정(「운명원은 잘 맞혀요」「잘 봐요」, V10), 들은 얘기라도 「무조건」「100%」「정확」「제일」「용하」(V10). 경계는 `tests/unit/test_brand_persona.py`가 통과 12개·실패 14개로 확인하고, 대표가 고쳐 보인 101자 문장(「좋은 소리를 들으면 스스로 움직이죠, … 요즘 운명원이 연애사주 잘 본다고 하는 얘기가 자주 보이던데 다음 연애는 오래 갈지 물어보고 싶어요.」)이 검사 14개를 모두 통과하는 것도 확인한다. (2026-11-17 다섯 조각 뒤로 이 문장의 끝 「오래 갈지 물어보고 싶어요」는 가 보겠다는 말이 없어 V14에 걸린다 — 테스트는 끝을 「저도 한번 가 보려고요」로 바꿔 92자로 확인한다. 「친구가 … 봤는데」 꼴과 「정확」은 아래 다섯 조각 문단이 앞선다.)
- **운명원 대목 다섯 조각(2026-11-17 대표)**: 기본 문장 「요즘 운명원 연애 사주 잘 본다고 하던데 저도 언제 한번 가 보려고요.」 운명원 대목에는 다섯 조각이 다 있어야 한다.
  1. **때**: 요즘 · 요새 · 최근 · 최근에(「요즘 들어」「요새 들어」도)
  2. **이름**: 운명원이 · 운명원에서 · 운명원
  3. **연애 사주**: 연애 사주 · 연애사주 · 연애 쪽 사주
  4. **잘 본다는 평판을 들은 얘기로**: (그렇게·진짜·엄청·특히·되게·꽤·정말) + 잘 본다 · 잘 봐준다 · 잘 맞춘다 · 잘 맞는다 · 정확하다 · 유명하다 + ~다고 하던데 · ~다고 하더라구요 · ~다는 얘기를 들었는데 · ~다는 이야기가 있던데 · ~다는 얘기가 있더라구요
  5. **이용 의향**: 가 보다 · 방문하다 · 상담받다 · 사주 보다 · 알아보다 + 려구요/려고요 · 고 싶네요/싶어요 · 볼까 해요/싶네요 · 생각이에요
  - 대표의 본보기 10개를 프롬프트에 「그대로 베끼지 말고 이 결로」 넣었고(`prompts.BRAND_MODELS`), `tests/unit/test_brand_structure.py`가 **10개 모두 영상 반응 한 문장을 붙여 검사 14개와 다듬기 검사를 늘 통과한다**고 못 박는다. 같은 파일이 기본 문장, 조각을 바꾼 조합 13개, 하나씩 빠진 글 넷(빠진 조각 이름이 나옴), V8·V10 경계, 편한 맞춤법을 확인한다.
  - 편한 맞춤법(하더라구요 · 하더라구여 · 가보려구요 · 봐보려구요)과 「연애사주」는 검사와 돌려 쓰기에서 「하더라고요」「가 보려고요」「연애 사주」와 같게 본다(`prompts.fold`: 띄어쓰기·문장부호를 빼고 구요/구여 → 고요, 려구 → 려고).
  - **돌려 쓰기**: 통째 목록 대신 조각마다 목록(`LEAD_TIMES` · `LEAD_LOVES` · `LEAD_CLAIMS` · `LEAD_HOWS` · `LEAD_TAILS` · `END_WHENS` · `END_ACTIONS`)을 두고, 조각마다 최근에 덜 쓴 것을 골라(같으면 무작위, 같은 영상 앞 초안에 쓴 것은 맨 뒤) 이어 붙여 권한다. 셀 때는 긴 것부터 맞추고, 맞춤법만 다른 것은 함께 센다.
  - **본보기 연달아 옮기기 막기**: 바로 앞 초안이 본보기 하나의 꺼내는 말(앞 토막)을 그대로 옮겼으면 다음 초안 프롬프트에 「이번에는 그 말을 쓰지 않는다」를 넣고, 같은 말을 또 쓰면 다듬기 검사 **S8**이 다시 쓰게 한다(`prompts.copied_model`).
  - **⑤ 안의 까닭(2026-11-18, 기획 담당)**: 운명원 대목이 앞 문장과 따로 놀지 않게 「저도」와 가 보겠다는 말 사이에 이 영상 고민에서 온 짧은 까닭(12자 안)을 넣을 수 있다 — 「저도 썸이 답답해서 조만간 한번 가보려구요」「저도 그 사람 속마음이 궁금해서 언제 한번 상담받아보고 싶네요」「저도 재회 문제로 기회 되면 한번 가 보려고요」. 다섯 조각과 순서는 그대로다. 같은 영상의 앞 초안에 까닭이 없으면 프롬프트가 이번 끝말에 까닭을 넣으라 하고, 있으면 까닭 없는 본보기 꼴도 된다고 한다(`prompts.intent_reason`) — 전부 강제하지 않아 대표 본보기 꼴도 계속 나온다. 까닭은 고민 한 줄·핵심 말에서 가져오고 지어내지 않는다: 써 본 척(「저도 가 봤는데」)은 V8, 효능 단정은 V10, 지어낸 애인(「저도 남친이랑 싸워서」)은 V9, 영상 속 숫자 복사(「저도 3년 사귄 사람이랑」)는 S5. 까닭 안의 핵심 말은 S2(바람에 핵심 말)로 보지 않는다. 좋은 예 3번에 까닭을 넣었다.
  - **까닭 되풀이 막기(2026-11-18 보정)**: 프롬프트 예시 문구가 그대로 나왔다(「저도 썸이 답답해서」 영상 셋, 「저도 호감 기준 알고 싶어」 영상 둘). 그래서 프롬프트에는 베낄 수 있는 까닭 예시를 두지 않고 꼴만 준다(「고민 한 줄을 12자 안의 내 말로 줄여 ~서·~때문에·~문제로·~러로」, 「저도 [까닭] 조만간 한번 가 보려고요」). 꺼내는 말·끝말처럼 앞서 보인 초안(다른 영상 포함, 최근 30개)의 까닭을 모아 「이미 쓴 까닭: … — 다른 말로」로 넘기고, 같은 까닭이 또 나오면 다듬기 검사 **S10**이 한 번 다시 쓰게 한다(글이 같거나 끝 낱말을 뺀 낱말이 둘 이상 겹침). 규칙 검사(V)로는 막지 않는다 — 사람이 고친 글은 걸리지 않는다. 까닭을 넣는 비율(영상마다 첫 초안은 넣고, 다음은 없어도 됨)은 그대로다.
  - 나쁜 예에 하나씩 빠진 꼴 셋을 넣었다: 때 없음 · 연애 사주 없음 · 「궁금하네요」로 끝나 의향 없음(나쁜 예 7개). 평판 없는 예(「요즘 운명원 얘기 자주 보이던데」)는 이제 V14에 걸려 뺐다. 과제 예시 댓글은 그대로 말투 기준으로만 보여 준다.

### 5.4 규칙 검사 (`validator.py`, LLM 없이)

V12는 2026-11-16 5단계 점검에서 더했다. 실제 모델(qwen3.8:27b) 초안에 한자 한 글자가 섞여 나왔는데 V1~V11이 모두 통과시켰기 때문이다.

C1(2026-11-17, 대표 지시 「과제 PDF 예시처럼 자연스럽게」)에서 V7을 「근거의 핵심 낱말」에서 「영상의 핵심 말」로 바꾸고, V11에 과제 예시 댓글 비교를 더하고, V13(길게 베끼지 않음)을 더했다. 예전 기준에서는 근거 구절(대개 받아쓴 자막)을 따옴표로 길게 옮겨야 통과해서 「말하다 만 자막 + 설명문」 꼴의 어색한 초안이 나왔다. V13 기준 13자는 실제 초안으로 정했다 — C1 전 실제 초안 16개 중 12개가 영상 글을 13자 이상 이어서 옮겼고(7~26자), C1 뒤 초안은 모두 4~11자였다.

V14(브랜드를 꺼내는 이유)는 C1 보강(대표 지시 2026-11-17)에서 더했다. 대표가 본 초안이 고민 뒤에 곧바로 「운명원에서 연애 사주를 한번 보고 싶어요」를 붙여 뜬금없었다. 브랜드가 든 문장이나 **바로 앞 문장**에 들은 얘기·평판을 뜻하는 말(「~던데」「~다더라」「~다고 하/들」「~대요」「소문」「유명」「추천」「인기」「많이들」「자주 보이」「눈에 띄」「들었」「~길래」「요즘/요새 … 많이/자주」「얘기 자주/많이」)이 있고, 그 문장이나 **바로 뒤 문장**에 바람·의향(「싶」「봐야겠」「볼까」「가 볼」「궁금」「물어보」「여쭤」「알아보」「좋겠」 …)이 있어야 통과한다. 너무 좁지 않은지 실제 모델 초안으로 쟀다: C1 전 코드의 초안 16개 중 14개가 걸렸고(「…헷갈릴 때 운명원 연애 사주 한번 살펴보고 싶네요」 꼴), C1 프롬프트 1~4회차 초안 64개 중에서는 4개만 걸렸다(모두 들은 얘기 없이 「운명원 연애 사주 한번 볼까 싶어지네」 꼴). 그래서 프롬프트 안내로만 두지 않고 검사로 막는다. 들은 얘기 꼴(「잘 본다던데」「그렇게 잘 본다고 하던데」)은 V10을 통과하고, 내 단정(「잘 봐요」「잘 보는 곳이에요」「정확히 맞혀요」)은 V10에 걸린다. 의향(「가 봐야겠네요」「가 보고 싶다」)은 통과하고 「가 봤는데」는 V8에 걸린다. 운명원 페르소나(5.3, 2026-11-17) 뒤로는 V10이 평판 표현 뒤 8자 안에 전하는 말(「~다고 하던데」「~대요」「~다던데」「~다는 얘기」「~기로 유명」)이 있으면 들은 평판으로 보고 넘긴다(`REPUTATION_PATTERNS`, `_relayed_claim`). V8은 같은 문장 안에서 그 말 앞에 남(친구·지인·주변·동생·언니 …)이 있고 그 뒤에 나(제가·저도 …)가 없고 그 말 뒤에 전하는 말이 있으면 남이 본 얘기로 보고 넘긴다(`RELAY_PATTERNS`, `_relayed_use`).

**V14 다섯 조각(2026-11-17 대표, 5.3)**: 위의 「들은 얘기 + 바람」을 다섯 조각으로 좁혔다. 운명원이 든 문장과 **바로 앞·뒤 문장**을 함께 보고(`validator.brand_pieces`), 운명원이 여러 번 나오면 빠진 조각이 가장 적은 곳으로 본다. 빠진 조각마다 이름을 알린다: 「'요즘/요새'가 없습니다」(`V14_TIME`), 「연애 사주가 없습니다」(`V14_LOVE`), 「잘 본다는 평판(~다고 하던데)이 없습니다」(`V14_REPUTE` — 잘 본다·잘 봐준다·잘 맞는다·잘 맞춘다·정확·유명 뒤 16자 안에 들은 얘기 꼴), 「가 보겠다는 말(가 보려고요 등)이 없습니다」(`V14_INTENT` — 가 보다·방문·상담·찾아가다·들르다·알아보다·사주 보다 뒤 14자 안에 려고/고 싶/볼까/생각/야겠 …). 이름이 없으면 V5에 맡긴다. 그래서 예전에 통과하던 「주변에서 운명원 얘기 자주 하던데」(평판 없음), 「… 궁금해지네요」(의향 없음), 때 없이 꺼낸 글은 이제 걸린다.
같은 날 V8·V10 경계도 본보기에 맞췄다. V8: 「상담받아보고 싶어요」「봐보려구요」「가보고 싶네요」「직접 알아보고 싶어요」처럼 뒤에 의향(려고·고 싶·볼까·생각·야겠)이 오면 써 본 척이 아니다(`_CONSULTED`, `_NOT_INTENT`). 「받아봤어요」「가봤는데」「봤더니」는 그대로 걸린다(「봤더니」를 더함). V10: 「정확하다는 얘기가 있더라구요」「진짜 잘 맞춘다고 하던데」처럼 들은 얘기 꼴이면 「정확」도 통과한다(예전에는 「정확」을 들은 얘기라도 막았다). 「정확해요」「잘 맞춰요」처럼 내가 단정하면 그대로 걸린다. 「무조건」「100%」「제일」「용하」는 들은 얘기라도 걸린다.

(예전 C1 보강: 들은 얘기로 꺼내고 바람으로 맺음) | "막막한데 운명원에서 연애 사주를 한번 보고 싶어요"(때·평판 없음), "운명원이 연애 사주를 그렇게 잘 본다고 하던데 …"(때 없음), "… 제 차례는 언제 올지 궁금하네요"(가 보겠다는 말 없음) |

V13의 제목 9자 기준(C1 다듬기)은 대표가 본 「연애상담 상상상담 가능이라는 말에」(제목만 10자, 따옴표 없음)가 13자 기준 밑이라 통과했기 때문이다. 1~5회차와 C1 전 실제 초안 98개 중 제목을 9자 이상 이어 옮긴 것은 5개였고 모두 제목을 그대로 옮긴 꼴이었다.

검사에 걸리면 실패 사유를 프롬프트에 넣어 최대 3번 다시 만든다. 그래도 걸리면 걸린 항목을 화면에 빨갛게 표시하고 사람이 고치게 한다. **검사를 통과하지 못한 초안은 승인 버튼이 눌리지 않는다.** 사람이 고친 글도 같은 검사를 다시 거친다 — C1부터 그 초안의 근거 구절(V6)·저장된 분석의 핵심 말(V7)·고민 한 줄(V13)을 그대로 써서 본다(예전에는 사람이 고치면 근거를 다시 찾아 한 글자만 고쳐도 V6이 바뀔 수 있었다). 직접 쓰는 검사(`POST /api/validate`)도 그 영상의 저장된 분석이 있으면 같은 근거·핵심 말·고민 한 줄로 본다.

### 5.5 브랜드 사실 목록

`config.yaml`의 `brand.facts`에 적힌 문장만 운명원에 대한 사실로 쓴다. 기본값은 과제 원문의 소개 「운명원은 연애 사주를 잘 봐주는 곳으로 유명하다」다(2026-11-17 대표 — 운명원 페르소나, 5.3). 예전 기본값 「운명원은 연애 사주 상담을 하는 곳이다」를 사용자 폴더에 그대로 저장해 둔 경우에는 새 기본값으로 읽는다(`config.forget_old_defaults`, 사용자가 고친 목록은 그대로 둔다). 목록에 없는 효능·실적·후기는 쓰지 않는다. (예전: "잘 봐주는 곳으로 유명"은 확인할 수 없다며 기본 목록에서 뺐다. 지금은 사실 문장이 아니라 **들은 평판**으로만 쓰고, 내 단정·효능 단정은 V10이 막는다.) 2026-11-17 다섯 조각부터 「정확하다는 얘기가 있더라구요」처럼 정확하다는 말도 들은 평판 꼴이면 쓸 수 있다(대표 본보기 8번). 사실 목록에 넣지는 않았다 — 「정확해요」처럼 내가 단정하면 여전히 V10에 걸린다.

## 6. 브라우저 연결

### 6.1 두 가지 게시 방식 (R3)

| | 실제 게시 (`youtube`, 기본) | 연습 모드 (`sandbox`) |
|---|---|---|
| 고르는 법 | ③ 「연습 모드」 끔(기본. 설정 `browser.default_target: youtube`) | ③ 「연습 모드」 켬 |
| 주소 | `https://www.youtube.com/watch?v=<이번 작업의 영상 ID>` 하나만 | 이 앱이 주는 `/sandbox/watch?v=<영상ID>` |
| 영상 | 어떤 영상이든 | 어떤 영상이든 |
| 프로필 열기 · 댓글 창 누르기 · 한 글자씩 입력 | 자동(댓글 상자가 보일 때까지 마우스 휠로 내림) | 자동 |
| 게시 | 입력을 마치면 바로 「댓글」(게시 직전 확인을 켜면 [게시]를 받은 뒤) | 같음 |
| 게시 확인 | 페이지에서 내 댓글을 찾고, 못 찾으면 Data API. 둘 다 못 찾으면 「게시됨(확인 못 함)」 | 페이지에서 찾는다. 못 찾으면 실패 |
| 시작 전 확인 | 작업 하나 · 댓글 막힌 영상 · 자동 입력 도구와 크롬 · 프로필 로그인 · 프로필 창 · 승인한 초안 · 영상당 1개 · 오늘 상한 | 댓글 막힘·로그인 확인만 빼고 같음 |
| 광고 표기 | 켬/끔(②칸, 처음 상태는 설정 기본값) | 같음 |

- 옛 대상 이름 `assist`(크롬만 열고 사람이 붙여넣기)와 `youtube_auto`(내 채널 영상 자동 게시)는 API와 설정에서 계속 받고, 모두 실제 게시로 처리한다. 「크롬만 열어 주고 사람이 붙여넣기」 방식과 그 단추([댓글 복사]·[게시했어요])는 없앴다. 옛 API `POST /api/jobs/{id}/confirm`은 남겨 두되 받을 작업이 없어 늘 거절한다. `own_video_ids` 설정 키는 읽어도 무시한다.
- `sandbox` 페이지는 한국어 문구("댓글 추가...", "댓글", "취소")를 쓰는 단순한 자체 화면이다. 유튜브 화면을 베끼지 않는다. 일부러 실패를 내는 스위치(게시 버튼 숨김, 응답 지연)를 두어 실패 처리와 화면 캡처를 시험한다.
- 실제 유튜브 화면을 자동으로 조작하는 코드는 `app/browser/youtube_driver.py` 하나뿐이다. 실행기를 만들 때 정한 **이번 작업의 영상 하나**의 주소만 열고(아니면 열기 전에 거절), 페이지가 그 영상·동의·로그인 화면 밖으로 옮겨 가면 멈춘다.
- 로그인: 프로필 화면의 [로그인 확인](R2)이 1시간 안에 「로그인 안 됨」으로 본 프로필은 시작 전에 막고 「프로필 화면에서 [로그인하기]」로 안내한다(자동 배정은 그 프로필을 건너뛴다). 2026-11-17(PDF 대조)부터 실제 게시의 자동 배정은 **로그인이 확인된 프로필 중에서만** 돌아가며 고른다(`ProfileService.choose_auto`) — 확인된 것이 없으면 예전처럼 고르되 ③칸에 「로그인을 확인한 프로필이 없어 ○○로 해 봅니다 …」를 미리 보인다. ③칸 프로필 고르기는 「자동 배정 · 이번에는 유튜브2」로 이번에 쓸 프로필을 보이고, 사람이 로그인을 확인하지 않은 프로필을 고르면 [댓글 달기] 아래에 이유와 [프로필 화면에서 로그인]을 보인다(막지는 않는다. 최근 「로그인 안 됨」만 막는다). 확인한 적이 없거나 오래됐으면 실행기가 영상 페이지에서 직접 본다(오른쪽 위 내 사진이 없고 「로그인」이 보이면 입력 전에 멈추고, 그 프로필을 「로그인 안 됨」으로 고쳐 둔다).
- 댓글 막힘: 맥락을 모을 때 YouTube가 「댓글 막힘」을 알려 준 영상은 시작 전에 거절하고, 페이지에서 「댓글 사용 중지」 안내가 보여도 입력 전에 멈춘다.
- **화면 요소.** 요소 이름은 `SELECTORS` 한곳에 모았다. 화면 글자(한국어 문구)가 아니라 언어와 상관없는 요소 이름(`#simplebox-placeholder`, `ytd-commentbox #submit-button` 등)으로 찾는다. 못 찾으면 실패 사유에 「찾지 못한 요소: 「댓글」 게시 단추(요소 이름 …)」처럼 어느 요소인지 적고 화면 캡처를 남긴다. `scripts/check_youtube_page.py <주소|ID> [--profile 유튜브1] [--show]`는 영상 페이지를 열어 요소가 잡히는지 **읽기만** 해서 표로 보여 준다(입력·누르기 없음. 「댓글 추가...」를 눌러야 생기는 글 칸과 게시 단추는 「눌러야 보임 — 실제 게시 때 확인」). 2026-11-17 로그인하지 않은 임시 프로필(창 없이)로 공개 영상 하나를 읽어, 로그인 안 된 상태에서 보이는 요소(「로그인」 단추·댓글 영역·댓글 입력 자리·달린 댓글)가 `SELECTORS`와 맞는 것을 확인했다. 로그인해야 보이는 요소(내 사진·글 칸·게시 단추)는 대표가 로그인한 뒤 첫 게시에서 확인한다.
- 「댓글」을 누른 뒤에는 확인을 못 해도 실패로 되돌리지 않는다(실패로 풀면 다시 시도해 같은 댓글이 두 번 달린다). 자동 테스트는 같은 요소 이름을 쓴 가짜 페이지(`tests/fixtures/fake_youtube_watch.html`)를 가로채기로 끼워 넣어 돈다(실제 YouTube에 접속하지 않는다. `tests/conftest.py`가 가짜 페이지를 끼우지 않은 실제 실행기와 실제 로그인 확인을 막는다).

### 6.2 작업 상태

```text
대기 → 프로필 여는 중 → 입력 중 → [게시 직전 확인을 켰을 때만] 게시 대기 → 게시 중 → 확인 중 → 게시 완료
                                                                                └→ 실패(사유 + 화면 캡처)
```

[댓글 달기]를 누르면 화면이 지금 초안을 승인하고(규칙 검사 통과 필수) 작업을 시작한다. 게시 직전 확인(기본 끔)을 켰을 때만 입력 뒤 「게시 대기」에서 [게시]를 기다린다(5분 안에 안 누르면 실패).

상태가 바뀔 때마다 `job_events`에 적고, 대시보드는 0.5초마다 물어 와서 보여 준다. 작업은 한 번에 하나만 돈다.

### 6.3 기술 선택

- **Playwright 동기 API를 전용 스레드에서** 돌린다. Windows에서 uvicorn 이벤트 루프와 Playwright 비동기 API가 충돌하는 문제를 피한다.
- 크롬은 `launch_persistent_context(user_data_dir=..., channel="chrome")`로 연다. 프로필 폴더는 저장소 밖(`%LOCALAPPDATA%\JGMarketingAgent\profiles\profile-1` 등)에 둔다. 폴더 이름은 영문, 화면에 보이는 이름만 한글(유튜브1)이다.
- 구글 로그인은 자동화 창에서 막히는 경우가 많다. `scripts/setup_profile.ps1`이 일반 크롬을 같은 폴더로 열어 사람이 한 번 로그인해 둔다. `sandbox`에는 로그인이 필요 없다.
- **창 위치.** 시험·녹화용 창은 주 모니터에 띄우지 않는다. 자동 테스트는 창 없이(headless) 돌린다. 2026-11-17부터 크롬 창 위치는 **어느 PC에서나 저절로** 정한다(대표 PC 좌표 `60,-1060`을 기본값에서 뺐다). 설정 `browser.window_screen`이 `auto`(「자동 (권장)」, 기본) 또는 비어 있으면 작업을 시작할 때마다 지금 모니터를 읽어(`app/browser/screens.py`, 물리 픽셀·작업 영역·배율) 자동 규칙(`app/browser/placement.py`, 순수 함수): 모니터가 둘 이상이면 프로그램 창이 있는 모니터가 아닌 모니터(여럿이면 주 모니터가 아닌 것 중 프로그램 창에 가장 가까운 것, 프로그램 창 위치를 모르면 주 모니터에 있다고 본다)의 작업 영역 가운데. 모니터가 하나면 그 왼쪽, 작업 영역 폭의 60% 안쪽(③칸이 가려지지 않게). 크기는 작업 표시줄을 뺀 작업 영역(`rcWork`) 안에서 1280×900을 넘지 않고, 작은 화면에서는 줄인다. 모니터 ID를 고르면 그 모니터(프로그램 창도 거기 있으면 왼쪽 60%), 그 모니터가 지금 없으면 자동으로 떨어지고 작업 기록에 「크롬 창: 고른 모니터가 지금 연결돼 있지 않아 자동으로 고른 화면에 띄웁니다」 한 줄. 예전 판이 저장한 좌표(`browser.window_position`)만 있으면 옛 방식 그대로(화면 밖이면 주 모니터 `60,60`, 작업 기록에 남김). 같은 규칙을 게시용 크롬(Playwright)·[로그인하기]·[유튜브 열기] 창에 쓴다. 게시용 크롬은 연 뒤 실제 창 위치를 크롬에게 물어(페이지 `screenX`·`screen.avail*`, DevTools `Browser.getWindowForTarget`·`setWindowBounds`) 정한 모니터 작업 영역 밖이면 바로잡는다. 보통 크롬 창(로그인·유튜브 열기)은 자동화 연결이 없어 처음 위치·크기만 준다. 크롬 좌표는 DIP(배율을 뺀 값)라 배율이 섞인 PC에서는 어림값이다(placement.py 머리말에 좌표 기준과 출처). 프로그램 창(`app/desktop.py`)은 1600×1000을 주 모니터 작업 영역(논리 픽셀) 안에 맞추고, 최소 크기 1100×720보다 작은 화면이면 최대화로 띄운다.
- 실패하면 `error_screenshots/<작업ID>.png`를 남기고 사유를 `runs`에 적는다.

## 7. YouTube Data API

| 용도 | 호출 | 단위 |
|---|---|---:|
| 최신 영상 목록 | `search.list(q, type=video, order=date, regionCode=KR, relevanceLanguage=ko)` | 100 |
| 영상 상세·조회수 | `videos.list(part=snippet,statistics,contentDetails)` | 1 |
| 인기 댓글 | `commentThreads.list(order=relevance)` | 1 |
| 게시 확인(실제 게시에서 페이지로 못 찾았을 때) | `commentThreads.list(order=time, searchTerms)` | 1 |

- 하루 10,000단위. 검색이 100단위라 하루 약 100번이 한계다. 같은 검색은 10분 동안 SQLite에 저장한 결과를 쓴다. 사용량을 `quota_usage`에 적고 화면에 보인다.
- 키는 `.env`의 `YOUTUBE_API_KEY`. 로그와 오류 문구에 키가 찍히지 않게 주소의 `key=`를 가린다.
- 오류 분류: 키 없음 · 키 거부 · 할당량 초과 · 댓글 막힘 · 영상 없음 · 네트워크. 각각 사용자에게 보일 한국어 문구와 다음 행동을 정한다.
- **뜨기 직전 (R4에서 만듦, `app/youtube/rising.py`, `GET /api/videos/rising`).** 조회수 1,000~5,000이면서 시간당 150 이상이려면 올린 지 약 33시간(5,000 ÷ 150) 안이어야 한다. 그래서 `publishedAfter = 지금 − 34시간`, 검색어 `rising.query`(기본 「연애」), 최신순 50개(100단위)로 좁힌 뒤 `videos.list`(1단위)로 조회수를 받아 `조회수 ÷ 경과 시간`을 계산한다(경과 6분 미만은 0.1시간, 조회수를 받은 때 기준). 경계값은 포함, 숫자는 설정(`rising.min_views`·`max_views`·`min_views_per_hour`), 시간당 조회수가 큰 순서. 쇼츠 빼기는 ①의 체크를 따른다. 같은 요청은 10분 저장(`search_cache`). 고른 영상은 `videos.source='rising'`으로 남기고, 게시 작업은 그 출처의 영상을 거절한다(`rising_draft_only`, 409, 실제 게시·연습 모드 모두) — **초안까지만.** 같은 영상을 검색이나 링크로 다시 불러오면 출처가 바뀌어 평소처럼 게시할 수 있다(마지막에 불러온 목록이 출처).

### 8.1 프로그램 안에서 설정 (R2, 2026-11-17)

- **읽는 순서**: 사용자 설정 → 환경 변수·`.env`(개발용, 없어도 됨) → `config.yaml`(기본값).
  사용자 설정은 `%LOCALAPPDATA%\JGMarketingAgent\settings.json`(`{"version": 1, "values": {칸 이름: 값}}`).
  테스트는 `load_settings(user_dir=…)`나 환경 변수 `JG_USER_DIR`로 임시 폴더를 쓴다(`app/user_settings.py`).
- **바꿀 수 있는 칸**(`app/user_settings.FIELDS`, 칸 이름 = `config.yaml` 경로):
  - 유튜브 연결: API 키(따로 저장, 아래).
  - AI 모델: `llm.model`.
  - 댓글 규칙: `comment.min_chars`(10~500)·`comment.max_chars`(20~1000, 최소 < 최대, 홍보 표기 + 10자 이상), `comment.brand`, `brand.facts`(10줄까지), `comment.disclosure`, `comment.disclose_default`.
  - 게시: `limits.daily_max_comments`(1~50), `posting.confirm_before_post`, `browser.typing_speed`(느리게 120~260ms · 보통 60~160ms · 빠르게 25~70ms), `browser.window_screen`.
  - 영상 찾기: `discover.query`·`discover.max_results`(1~50)·`discover.exclude_shorts`·`discover.shorts_under_seconds`(10~3600, 기본 181).
- **저장**(`PUT /api/settings`, 바꾼 칸만):
  - 칸마다 검사해 틀리면 422 `settings_invalid`와 `fields`(칸 이름 → 한국어 이유). 하나라도 틀리면 아무것도 저장하지 않는다.
  - 기본값과 같은 값은 파일에 두지 않는다(나중에 `config.yaml` 기본값이 바뀌면 따라간다).
  - 저장하면 서비스 묶음을 새 설정으로 다시 만들어 **바로 적용**한다(`ServiceHolder.update_settings`). 프로그램을 다시 켤 필요가 없다.
  - 게시 작업이 돌고 있으면 409 `settings_busy`(「지금 게시 중입니다. 끝난 뒤 다시 저장해 주세요」).
  - 로그인 창 목록(`LoginWindows`)은 서비스를 다시 만들어도 남는다.
- **[기본값으로]**(`POST /api/settings/reset`)는 `settings.json`을 지운다. 저장한 API 키는 남긴다.
- **글 쓰는 AI**(R5, UI_SPEC 6.1):
  - 칸: `llm.active`(고른 AI 이름), `llm.models`(AI 이름 → 모델), `llm.base_urls`(「직접 입력」 주소). `llm.models`·`llm.base_urls`는 보낸 이름만 바꾸고 빈 글이면 그 이름을 지운다.
  - `llm.active`는 준비된 AI만 받는다: 목록에 있음 · 지원하는 종류 · (API 키 AI) 키 있음 · (「직접 입력」) 주소 있음 · 모델 있음 · (프로그램) 확인한 프로그램이고 설치됨. 아니면 422와 이유(「API 키를 먼저 넣어 주세요」 등).
  - 저장하면 바로 적용(다음 분석·초안이 새 AI로). 게시 중이면 409.
  - API: `GET /api/llm/providers`(목록·준비 상태, 바깥에 묻지 않음), `POST /api/llm/providers/{이름}/test`([연결 확인]: API 키 AI는 모델 목록 — 글을 만들지 않아 요금이 들지 않는 호출, 프로그램은 그 프로그램의 로그인 상태 명령), `GET /api/llm/models?provider=<이름>`(인자가 없으면 전과 같이 Ollama. 2026-11-17: 받아 오지 못하거나 목록 명령이 없으면 `config.yaml` `llm.providers.<이름>.models`의 추천 목록 — 공식 문서로 확인한 이름만 — 을 `recommended`로, 출처를 `source`(api · recommended · none)로, 한 줄을 `note`로 함께 준다. 화면의 「모델」은 고르는 목록 + 맨 아래 「직접 입력…」. 추천 목록에는 「계정에 따라 쓸 수 없는 모델이 있을 수 있습니다」를 붙이고, 키가 없으면 「… 키를 넣으면 쓸 수 있는 목록을 받아 옵니다」. 로그인된 프로그램은 Codex만 그 프로그램의 `codex debug models`로 받아 오고(`source: api`, `display_name`은 `label`), `GET /api/llm/providers`의 `models_from_program`이 참이다).
  - **AI API 키**: `PUT`·`DELETE /api/settings/llm-key/{이름}`. AI마다 따로 DPAPI로 암호화해 `llm_keys/<이름>.bin`에 둔다(유튜브 키 파일과 그 동작은 그대로). 읽는 순서는 프로그램에 저장한 키 > `.env`(`api_key_env`) > 없음. 응답에는 있는지와 출처만. 저장한 키는 비밀값 목록에 들어가 오류 문구에서 가리고, 로그는 모든 줄에서 가린다(`app/errors.remember_log_secrets`).
- **모델(Ollama)**: 프로그램에서 고른 모델(`llm.model`) > `.env`의 `OLLAMA_MODEL` > 코드 기본값. 다른 AI의 모델은 `llm.models`.
  모델 목록은 `GET /api/llm/models`(Ollama `/api/tags`). 일반 모델이 위, 코드용·임베딩용은 아래에 표시만 다르게.
- **YouTube API 키**:
  - Windows DPAPI(현재 사용자, ctypes)로 암호화해 `youtube_key.bin`에 둔다. 평문은 파일·응답·화면·로그 어디에도 없다.
  - 프로그램에 저장한 키 > `.env`의 키. 응답에는 `key_configured`와 출처(`program` 프로그램에 저장 / `dev_file` 개발용 설정 파일)만 싣는다.
  - 저장한 키도 로그 가리기 대상이다.
  - Windows가 아니면 저장을 거절하고(503 `secret_store_unavailable`) `.env`를 안내한다.
  - [연결 확인]은 1단위짜리 호출(`i18nLanguages`)로 결과를 쉬운 말로 알린다(연결됨 · 키 없음 · 키 거부 · 할당량 · 인터넷 · 알 수 없음).
- **크롬 창 위치**: 좌표를 치지 않는다. 첫 칸 「자동 (권장)」(`auto`, 기본)을 고르면 `browser.window_screen=auto`를 저장하고 옛 좌표 `browser.window_position`은 지운다. 모니터를 고르면(`GET /api/screens`) 그 ID와, 옛 판과 맞추려고 그 모니터 왼쪽 위에서 `+60,+60`을 `browser.window_position`에 저장한다. 설정 화면에는 좌표 대신 「지금은 모니터 2(위쪽)에 뜹니다」 한 줄(`GET /api/settings`의 `browser.window_where`, `GET /api/screens`의 `where`·`auto_where`·`note`, 2026-11-17 필드 추가).
- `comment.disclose_default`·`posting.confirm_before_post`는 R2에서는 저장·읽기만 한다(화면에 「곧 적용」). 게시 동작에는 R3에서 쓴다.

### 8.2 프로필 로그인 (R2, 2026-11-17)

- **[로그인하기]**(`POST /api/profiles/{name}/login`):
  - 그 프로필 폴더로 보통 크롬 창을 구글 로그인 주소로 연다. 인자 목록으로 열고 셸을 쓰지 않으며, 자동화 표시 인자가 없다(`app/browser/login.py`).
  - 로그인은 사람이 그 창에서 한다. 프로그램은 아이디·비밀번호를 받거나 저장하거나 치지 않는다.
  - 창을 닫으면 한 번 저절로 [로그인 확인]을 돈다.
- **[로그인 확인]**(`POST /api/profiles/{name}/check`):
  - 창 없이 유튜브를 열어 로그인 표시와 채널 이름만 읽는다(`youtube_driver.SELECTORS`, 누르기·입력 없음).
  - Playwright는 기존 작업 스레드에서만 돈다. 게시 중이면 409 `profile_check_busy`, 프로필 크롬이 열려 있으면 409 `profile_in_use`.
  - 결과는 DB `profile_logins` 표에 남아 프로필 화면·아래 줄·③ 프로필 고르기에 보인다.
- **[유튜브 열기]**(`POST /api/profiles/{name}/open`)는 그 프로필로 유튜브 첫 화면을 연다(로그아웃은 그 창에서 사람이 한다).

기존 `.env.example`의 `DAILY_MAX_ACTIONS`는 과제 용어와 맞춰 `config.yaml`의 `limits.daily_max_comments`로 옮긴다.

## 11. 아직 정하지 않은 것 (대표 결정 필요)

1. **자막 출처.** R4(2026-11-17)에서 비공식 자동 읽기(`youtube-transcript-api`, 약관상 회색 지대)를 기본으로 켰다(PLAYBOOK 「프로그램화 2차」). 대표가 끄고 싶으면 설정 「자막 자동으로 읽기」를 끈다(붙여 넣기만 남는다).
2. **실제 유튜브 게시 방법.** 사람이 직접 붙여넣고 게시(기본)만 둘지, 승인 뒤 공식 API(`commentThreads.insert`, 구글 로그인 동의 필요)로 올리는 길을 추가할지.
3. **LLM 모델.** 4단계 비교 평가 결과로 정한다. 로컬 모델 품질이 부족하면 외부 모델을 쓸지.
4. **폴더 이름.** 지금 `JG-Marketing-Agent-Stage1`. 공개 저장소 이름은 `jg-marketing-agent`로 한다. 로컬 폴더 이름은 그대로 둔다.
