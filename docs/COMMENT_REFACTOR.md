# 댓글 생성·검수 모듈 리팩토링 지시서 (2026-11-18 최종)

대표가 Fable 5.2와 인터뷰로 확정한 지시서다. 구현은 Opus 5.5. 이 문서가 댓글 생성·검수의 기준이며,
DESIGN·INTENT의 예전 설명(조각 맞추기·이야기처럼·V1~V14)보다 앞선다.

## 0. 범위

- 그대로 둔다: 유튜브 수집(`app/youtube/`), 자막(`app/transcript/`), 영상 분석(`app/analysis/analyzer.py`),
  컨텍스트(`app/analysis/context.py`), 브라우저 게시(`app/browser/`), DB 스키마(`app/db.py`),
  API 주소와 응답 모양(`app/api/drafts.py`, `app/api/validate.py`, `app/schemas.py`).
- 화면(`app/static/`)은 설정의 「댓글 쓰는 방식」 선택 칸 하나만 뺀다.
- 댓글 생성과 검수 로직만 처음부터 다시 쓴다. 쓰는 방식은 하나만 남긴다.
- 이번에는 새 템플릿, 문장 조각, 끝말 순환, 새 정규식 검사를 만들지 않는다.
- 지우기 전에 기존 코드의 참조 관계(import, 호출하는 쪽, 테스트, 스크립트)를 먼저 확인한다.

## 2. 페르소나

영상을 방금 본 20~30대 시청자. 한 사람으로 고정하지 않는다. 댓글에는 네 가지가 들어간다.

1. 영상의 구체적인 장면이나 말 하나에 대한 반응
2. 영상을 보다 떠오른 내 연애 고민 한마디(영상 속 상황과 똑같지 않아도 된다. 날짜·사람·사건은
   지어내지 않는다)
3. 운명원이 연애 사주를 잘 보기로 유명하다는 것(뜻만 같고 표현은 자기 말투로)
4. 그 고민을 풀려고 운명원에 연애 사주를 보러 가겠다는 다짐과, 거기서 무엇을 알고 싶은지
   (알고 싶은 것은 내 고민의 답이어야 하고 영상 내용과 맞아야 한다. 범위를 정해 주지 않는다)

다짐은 묻거나 망설이는 말이 아니라 스스로 다짐하는 말투다. 댓글 안에서의 위치는 정하지 않는다.

## 3. 누가 무엇을 정하나

| 정하는 것 | 누가 | 어떻게 |
|---|---|---|
| 말 높임 | 코드 | 반말 혼잣말 / 존댓말 중 하나를 무작위로(「섞임」은 실제 22개에서 한 댓글 안에 어색하게 섞여 2026-11-18 대표가 뺐다) |
| 운명원을 들은 경로 | 코드 | 요즘 자주 들어서 / 요새 여기저기서 들어서 / 예전에 어디선가 들어서 중 하나(친구·지인은 2026-11-19 대표가 뺐다. 8절) |
| 들은 말의 요지 | 코드 | 핫하다 / 잘 본다 / 유명하다 / 연애 사주 하면 운명원 중 하나(8절) |
| 짚을 내용의 출처 | 코드 | 분석기 근거를 자막 → 제목·설명 → 인기 댓글 순으로 고른다 |
| `[광고]` 붙이기 | 코드 | 켬/끔에 따라 맨 앞에 붙이거나 뗀다 |
| 기분 | AI | 영상 분위기와 고민에 어울리게 |
| 짚을 장면, 내 고민 | AI | 받은 자료 안에서 |
| 운명원에서 알고 싶은 것 | AI | 영상과 고민에서 나온 것을 자유롭게 |
| 평판을 말하는 표현, 순서, 문장 수, 끝말 | AI | 자유 |

- 후보 목록은 코드에만 둔다. 프롬프트에는 뽑힌 값 하나만 들어간다.
- 같은 영상에서 [다른 댓글 만들기]를 하면 직전 초안과 다른 말 높임·들은 경로 조합을 뽑는다.
- 코드가 뽑은 두 값과 AI가 적어 낸 기분은 기존 `drafts.tone_label` 칸에 " / "로 이어 저장한다.
  다시 쓸 때는 여기서 읽어 같은 말 높임·들은 경로로 쓴다.
- AI가 적어 낸 `wish`(알고 싶은 것)는 DB 칸을 늘리지 않고 기존 JSON 칸에 함께 저장한다.

## 4. 생성 프롬프트 (`app/llm/prompts.py`)

> 2026-11-19: 아래 틀은 처음 지시서다. 지금 틀은 8절(참고 댓글 · 들은 말 요지 · 다른 영상 최근 댓글)을 따른다.

시스템 글은 아래 틀 그대로 쓴다. 문구 예시·끝말 본보기·광고 언급·사주 갈래 목록을 더하지 않는다.
[운명원]의 첫 줄은 설정 `brand.facts`에서 읽어 넣는다.

```text
너는 방금 이 유튜브 영상을 본 20~30대 시청자다. 영상 밑에 댓글 하나를 단다.

[운명원]
- 연애 사주를 잘 보기로 유명한 곳이다.
- 너는 이것을 {들은 경로} 알게 됐고, 가 본 적은 없다.

[이번 댓글을 쓰는 너]
- 말: {말 높임}
- 기분: 이 영상의 분위기와 네 고민에 어울리게 네가 정한다.

[쓰는 법]
- [짚을 내용]에 있는 장면이나 말 하나를 짚어 반응한다.
- {근거가 댓글일 때만 넣는 줄}
- 영상을 보다가 네 연애 고민이 떠올랐다. 영상 속 상황과 똑같지 않아도 된다. 고민은 한마디로만 말하고 날짜·사람·사건은 지어내지 않는다.
- 그 고민을 풀고 싶어서 운명원에 연애 사주를 보러 가기로 마음먹었다. 남에게 묻거나 망설이는 말이 아니라 스스로 다짐하는 말로 쓴다.
- 운명원에서 무엇을 알고 싶은지를 댓글에 꼭 쓴다. 이 영상의 내용과 네 고민에서 나온 것이어야 한다.
- 운명원이 어떤 곳인지 댓글에서 한 번 말한다. [운명원]의 문장을 그대로 옮기지 않고 네 말투로 바꿔 말한다.
- 어떻게 알게 됐는지는 네가 아는 사실일 뿐이다. 글이 어색해지면 댓글에 밝히지 않아도 된다.
- 순서, 문장 수, 끝말은 자유다.
- 본문은 공백 포함 40~120자, 한 줄이다. 80~100자쯤을 목표로 쓴다.
- 쓰지 않는 것: 운명원에 가 본 듯한 말, 효과를 단정하는 말, 링크, 해시태그.

출력(JSON): {"mood": "네가 정한 기분 한 낱말", "body": "댓글 본문", "wish": "운명원에서 알고 싶은 것 한 구절", "used_quote": "[짚을 내용]에서 네가 짚은 구절 그대로"}
```

`{근거가 댓글일 때만 넣는 줄}`:
"이 얘기는 영상이 아니라 다른 시청자의 댓글에 나온 것이다. 댓글에서 봤다는 것을 밝히고 공감한다.
위·아래 같은 위치는 말하지 않는다."
근거가 자막·제목·설명이면 이 줄을 통째로 뺀다.

요청 글에 넣는 것:
- 영상 제목과 분석의 고민 한 줄
- [짚을 내용]: 분석기가 뽑은 근거 구절(출처 표시)과 관련 자막. 고르는 순서는 아래와 같다.
  1. 자막에서 나온 근거가 있으면 그 근거와 자막 앞부분
  2. 자막이 없으면 제목·설명에서 나온 근거
  3. 자막·제목·설명에서 고민을 찾지 못했을 때만 인기 댓글에서 나온 근거
- [다른 댓글 만들기]일 때만: 같은 영상에서 이미 짚은 구절과 앞 댓글의 `wish`
  (그 장면은 피하고, 이 영상에 맞는 다른 궁금증이 있으면 그쪽으로)
- 다시 쓸 때만: 앞의 본문과 걸린 사유

넣지 않는 것: 이전에 쓴 댓글 본문, 댓글 예시, 끝말 본보기, `[광고]`·홍보에 대한 말.

코드가 하는 것:
- `[광고] `는 지금처럼 `drafter.py`가 켬/끔에 따라 붙이고 뗀다.
- `used_quote`는 기존 `drafts.evidence_quote` 칸에, 출처는 `evidence_source` 칸에 저장한다.

## 5. 규칙 검사 (`validator.py`, `checking.py`): 게시를 막는 것은 이것뿐

검사 번호는 바꾸지 않는다. 기존 함수와 표현 목록을 그대로 쓰고 새 정규식을 만들지 않는다.

| 번호 | 내용 |
|---|---|
| V1 | 본문 40~120자(`[광고]` 빼고 센다), 한 줄 |
| V2 | 링크 없음 |
| V3 | 해시태그 없음 |
| V4 | 광고 표기를 켰으면 `[광고]`로 시작(끄면 「표기 끔」으로 통과) |
| V5 | `운명원` 포함, 그리고 글 안에 '연애'와 '사주'가 둘 다 있음(기존 검사 그대로. 붙은 꼴만 요구하지 않는다) |
| V6 | `used_quote`가 실제 영상 자료에 있음(기존 대조 함수 그대로) |
| V8 | 써 본 척하는 후기 없음("가봐야겠다", "상담받고 싶어요" 같은 의향은 통과) |
| V9 | 지어낸 구체적 사연 없음(막연한 처지 "연애만 하면 차이는 편", "짝남이 있다"는 통과) |
| V10 | 효능 단정·지어낸 평판 없음(V14의 지어낸 평판 검사를 여기로 합친다) |
| V11 | 이전에 승인·게시한 글과 글 전체가 사실상 같지 않음 |

- `strip_hashtags`, `ValidatorRules`, `parse_extra_patterns`는 유지한다.
- `validate()`와 `CheckService.check()`는 호출하는 쪽(API, 사람이 고친 글 재검사)이 깨지지 않게 한다.
- V9는 구현 전에 막연한 처지 문장이 통과하는지 테스트로 먼저 확인한다.

## 6. 생성·검수 흐름 (`drafter.py`, `review.py`)

생성 `generate()`:
1. 코드가 말 높임·들은 경로를 뽑고, [짚을 내용]을 우선순위대로 고른다.
2. AI가 댓글을 쓴다.
3. 규칙 검사. 걸리면 걸린 사유만 알려 주고 같은 말 높임·들은 경로로 다시 쓴다(다시 쓰기는 최대 2번).
4. 끝까지 걸리면 걸린 것이 가장 적은 글을 저장하고 걸린 항목을 표시한다.

검수 `review.py`:
- 유지: `review_json`, `review_status`, `POST /api/drafts/{id}/review`, 결과 이름(passed, rewritten,
  flagged, error, off)과 `schemas.py`가 참조하는 이름.
- 판정하는 것은 셋뿐이다.
  1. 댓글이 짚은 장면이나 말이 실제 영상 자료에 있는가
  2. 운명원에서 무엇을 알고 싶은지가 댓글에 적혀 있고, 그것이 댓글에 나온 내 고민의 답이며 영상
     내용과 맞는가(유명해서 간다고만 하거나, 고민과 다른 것을 보러 간다고 하면 거짓)
  3. 문장이 말이 되는가(말 높임이나 들은 경로 때문에 억지스러운 문장 포함)
- 맞춤법·구어체(ㅋㅋ, ㅠㅠ, "가려구요")는 보지 않는다. 분명할 때만 거짓, 애매하면 참.
- 판정과 별도로 분류 한 칸을 답한다: 댓글이 알고 싶어 한 것이 「인연이 오는 때 / 잘 맞는 사람 / 궁합 /
  반복되는 연애 패턴 / 기타」 중 어디인가. 통계용이며 통과 여부에 쓰지 않는다. 억지로 네 갈래에 넣지
  않고, 해당이 없으면 기타로 둔다. 쓰는 AI에게는 이 갈래를 알려 주지 않는다.
- 답은 `{"ok": 참/거짓, "problems": [한 줄, …], "wish_kind": "갈래 이름"}`.
- 검수하는 AI에게는 쓰는 AI가 본 것과 같은 영상 자료를 준다.
- 거짓이면 같은 말 높임·들은 경로로 한 번 다시 쓰고 다시 검수한다. 다시 쓴 글이 규칙 검사에 걸리면
  앞 글을 둔다.
- 검수는 게시를 막지 않는다. 검수 호출이 실패하면 초안은 그대로 두고 「검수 못 함」으로 남긴다.

## 7. 검증과 마무리

- `pytest`와 `.\scripts\verify.ps1`이 통과해야 한다. 자동 테스트는 인터넷·API 키·AI 없이 돈다.
- 실제 모델로 영상 11개 × 2 = 22개를 게시 없이 뽑아 보고서를 만든다. 영상은 썸, 이별, 연애 심리,
  연락 문제가 섞이게 고르고, 자막 없는 영상을 하나 이상 넣는다.
  - 초안마다: 말 높임, 들은 경로, 기분, 알고 싶은 것과 그 갈래, 영상, 요약 고민, 댓글, AI 검수,
    다시 쓴 횟수와 이유, 최종 실패
  - 최초 생성 품질: 첫 시도 규칙 검사 통과 수, 첫 검수 통과 수, 걸린 사유별 개수
  - 반복성: 갈래별 개수(기타 포함), 끝말이 글자까지 같은 것의 개수, 운명원 소개 문장을 거의 그대로
    옮긴 것의 개수
- 22개에서 문제가 확인되면 대표에게 보고한다. 대표가 정하기 전에 장치를 더 넣지 않는다.
- 문서를 실제 상태로 고친다: AGENTS 절대 규칙 1(「V1~V14」)·2, INTENT 2~4절, DESIGN, CHANGELOG, README.
- 보고는 "구현함 / 자동 검증함 / 사람이 확인함 / 안 함"으로 나눈다.

## 8. 2026-11-18~19 대표 목표로 바꾼 것(회차 실험)

대표 목표: 「AI 티가 안 나며, 맥락이 유지되고, 연애 사주로 유명한 운명원(모두 동일하면 안 됨)을
간접적으로 바이럴 마케팅하는 댓글」. 기준은 대표가 쓴 예시 5개다. 판정 우선순위는 AI 티 없음 > 맥락 >
운명원 간접 홍보이고, 완벽한 중복 회피가 아니라 한 틀로 찍혀 나오지만 않으면 된다.

- 시스템 글: [운명원] · [댓글에 들어갈 것](장면 반응 · 떠오른 내 처지 한마디 · 들은 얘기 · 처지에서
  나온 사주 궁금증과 보러 가 봐야겠다는 마음) · [말] · [참고 댓글] · [지킬 것]. 완성 문장을 주면
  그대로 새어 나와 굳었다(0회차).
- [참고 댓글]: 뽑힌 말 높임의 대표 예시만(`prompts.VOICE_SAMPLES`). 4절의 「예시 없음」을 대표가 바꿨다.
  친구·지인·주변 말은 요즘·요새 말로 바꿨다(2026-11-19).

  뽑고 다른 영상 최근 두 댓글이 쓴 계열은 피한다. 요지가 있으면 [운명원]에 소개 문장(`brand.facts`)

  겹치지 않게 한다. 4절의 「이전 댓글 본문을 넣지 않는다」를 다른 영상 것에 한해 바꿨다.
